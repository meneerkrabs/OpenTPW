# OpenTPW progress entry and lifetime

This is one application-owned progress file, not a native player profile or lobby
reproduction. The model defaults remain zero earned and zero extra keys; missing
storage means unknown history. No legacy theme counts or unseen save files supply
player-wide history.

The actual New Full Simulation action checks a required `Keys.CostToEnter` integer
from the selected canonical theme's `global.sam`. Missing, malformed, negative or
out-of-range metadata refuses; the balance reader's missing-file zero fallback is
not authorization. Existing lazy browser level preparation runs before the final
check, while the current scene stays live. The gate runs before any candidate
world construction and checks cost/profile again at candidate precommit.

If own history is missing, New offers explicit opt-in through the existing message
window. Confirm stages a new Full Simulation ledger with one extra key, admitting
only a nonnegative cost at most one. It does not change the model's zero default.
Profile publication occurs atomically before retiring the old scene. A failed
write retains that scene and any prior file; a successfully created profile stays
created if later activation fails. Reopening/retrying never grants a second key.
Known zero-key and Instant Action ledgers are not reset or migrated. New Instant
Action bypasses key costs and creates no progress file.

Manual Continue and Load preserve their saved mode/start and are never key-gated.
A missing, incompatible or malformed progress file may disable tracking with an
explicit notice, while the resumed park remains playable. With compatible known
Full Simulation progress, only explicit identities of the current admitted park
are reconciled. The runtime owner excludes reference inspection, sandbox,
read-only visits, Instant Action and the unsupported TPI economy context.

The owner subscribes the exact `ParkEconomyRuntime`, not a captured economy.
`GoldenTicketWon.Amount` supplies the kind, checked against the current objective
set. Economy replacement is reconciled, and retirement unsubscribes the owner.
The six local, four global and two secret scopes follow the ledger contract;
existing host AllLandOwned storage makes no new native earning claim.

Failed persistence keeps earned identities in memory. Normal Exit, New, Load,
Continue, Visit and UI Quit flush before abandoning pending work or retiring the
old world; failure keeps the live world and allows retry. A queued request and
candidate commit recheck the owner. Cancellation wins combined input, captured
or retired callbacks cannot start a park, and stale error callbacks cannot pop a
fresh screen. Notifications belong to their owner and do not duplicate an already
shown refusal.

A SHA-256 digest is calculated from the same capped bytes that were parsed. Any
observed change before overwrite refuses instead of replacing another state.
This is optimistic single-owner detection, not cross-process compare-and-swap or
an atomic transaction joining a profile and world. Forced OS termination, browser
storage durability and post-retirement hardware failure recovery are unqualified.
There is no native GMS writing, named-profile UI, global mystery transaction, TPI
progression or original-executable parity claim.

Synthetic controls use actual menu dispatch, guarded GameFlow bindings, isolated
candidate precommit seams, real temporary/rename refusal, actual economy awards,
loaded runtime replacement and dirty retirement/retry. Terrain/GPU/windowed
candidate activation and original shipped metadata have not been freshly executed.

Independent ingress controls also pin declared zero cost without resetting Full
or Instant Action history, raw-byte digest changes, theme lease changes, late
candidate precommit refusal, bounded profile reads, checked award amounts and
exact runtime unsubscribe. A failed dirty level-queue flush retains the pending
action, live world and its hash, then persists the earned identity on retry.
These controls do not qualify cross-process writes or rendered activation.
