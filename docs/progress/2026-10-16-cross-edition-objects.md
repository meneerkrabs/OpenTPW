## Cross-edition objects extension: id ranges, sound banks per root and the Theme Park Inc opcodes (October 16, 2026)

Phase 6 of the mod system (docs/MODS.md), the engine side of the official extension `opentpw.cross-edition-objects` that lets a data mod bring Theme Park Inc attractions into Theme Park World. The user supplies the Theme Park Inc install; nothing of it ships. Loading the archives needs the data content roots of phase 5, so this step carries the rules and the loading follows.

- **The extension** is registered, off by default and marked as changing the simulation (`[EXT:cross-edition-objects]`); `FeatureGates.CrossEditionObjects` reads it. A mod that depends on it is refused while it is off; while it is on, park saves record it (`ModSet.SimulationMods`) and require it to load.
- **Info.Id ranges.** 168 of the 202 distinct Theme Park Inc ids are also Theme Park World ids, 145 of them for other objects, and the original keeps only the first definition by id reachable (RIDES-024, `0x412e90`). One rule for every mod's range, applied by `ModObjectsFile` (`CrossEditionObjects.RangeProblem`): 5000 to 65535, at most 4096 ids, above the 4605 (Theme Park World) and 4500 (Theme Park Inc) maximum original ids (both measured by tests against the installs) and inside the 16-bit Info.Id (`mId`) of the original saves. The range is declared once, in the `idRange` of `objects.json`, which already refuses an id outside the range, a repeated id, a missing range and, in `ModSet`, overlapping ranges; the content roots' earlier bounds (10000 to 1000000000, at most 1000 ids) are replaced by this rule, and the manifest has no second field.
- **Sound banks per content root** (`ContentSoundRoots`, `SoundRoot`). The `EVENT` ids of a Theme Park Inc ride name events of Theme Park Inc's own catalogues (global `cat_rides` has 114 events against 25 here), so RSE `EVENT` types 3 to 9 from an object of a registered root are looked up in that root's categories (level categories by the archive's own theme), with no fallback to the running game's, as the original has none. All Theme Park Inc ride and ambient banks resolve in the Theme Park Inc root (checked against the install). Without a registered root nothing changes.
- **The two Theme Park Inc opcodes** WAITABS (45) and MULT (48) were read in `Game.exe` (jump table `0x6ab5f0`, handlers `0x6a8b7e` and `0x6a9108`) against tp.exe (`0x5567d8`, `0x553828`, `0x553eb9`): the same operand decoding and effect, so they need no new VM support and are not Theme Park Inc only (`docs/TPI-COMPARISON.md` corrected, `[BIN:TPI-EXE]` labels added). The Theme Park Inc clock object is a different instance with the same base plus `+0x48` shape.
- **Missing economy keys**: measured over the 183 Theme Park Inc archives that map onto the four Theme Park World themes, with Theme Park World's category defaults under them every key all Theme Park World objects of the category carry is present, so no per-key default is needed; `Upgrades[n].RunningCost` has no Theme Park World counterpart and is ignored, and `Research.Group` up to 6 already opens like the original's zero-filled `ResearchTech` block.

The pinned determinism hashes are unchanged (the extension is off by default and nothing else moves). Still open: loading Theme Park Inc archives through content roots with the mapped ids and TPW category defaults, the economy catalogue merging those objects, recording the extension in park saves, fixed-id sounds (screams, repair sounds) and level music for objects of another root, and the two Theme Park Inc `MusicHD.sdt` banks that the reader only partly accepts.
