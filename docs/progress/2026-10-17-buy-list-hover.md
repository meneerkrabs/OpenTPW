## The buy list selects the row under the pointer (October 17, 2026)

- **The original.** The buy window's list (control 504, attribute `0x91`) includes attribute `0x80`, so every pointer move over it (messages `0x10001` and `0x10003`, `0x665c35`) runs `0x6656a0`: the row under the pointer is selected through `0x66552e` and `0x66525c`, the same path a click or an arrow key takes (`0x665739`). The selection posts `0x401` to the window, whose handler `0x4ac9e8` refreshes the stats frame at once (`0x4abb00`) and arms the preview; the update (`0x4ac42e`) makes the preview object, footprint and name (`0x4ab1b0`) once the clock is more than 500 ms past the last change.
- **Leaving and clicking.** The list handles no message for the pointer leaving, and a pointer below the last row leaves the selection alone (attribute `0x100` is not set), so the selection stays on the last hovered row. A left click selects the row and posts `0x400` (`0x6655a2`), which is the purchase (`0x4ac4f9`); the other button posts `0x402`, which the window ignores, so it backs out.
- **What changed.** Hovering a row selects it, the stats follow immediately and the preview after 500 ms (also for the first preview when the window opens), a left click buys even without a prior hover, and the loans list (same attribute, `0x49f4e0` handles only `0x400`) selects on hover too. The original sends the pointer messages only when the pointer position changes (`0x658840`), so the arrow keys and the wheel keep their selection under a resting pointer, while any pointer move selects the row under it again. The Load Park list (attribute `0x81`) selects on hover and loads on one click in the original; OpenTPW keeps click-to-select there and registers the difference as UI-108.
