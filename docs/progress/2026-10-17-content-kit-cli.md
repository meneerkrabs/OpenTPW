## Content kit: glTF converter, TGA writer and the `opentpw-kit` command line (October 17, 2026)

The last piece of phase 0 of the content pipeline: a Blender export now turns into a mod object the game loads ([CONTENT-KIT.md](../CONTENT-KIT.md)).

- **`GltfModelConverter`** (glTF to `ModelBuilder`): the node hierarchy (a dummy root for several roots), local transforms, one MD2 mesh per mesh node with one material per glTF material, corners de-duplicated per material, normals and UVs, wrap and self-lit material extras, rider-head extras, texture names from the image names, and clear refusals (no UVs, no texture, more than 65,535 corners, long or duplicate names, bad head ids, non-finite numbers). `ModelBuilder` gained `SelfLit` (material word +0xC bit 0x1).
- **Two conventions, with evidence.** Texture V is stored bottom-up (`V = 1 - v`): the object shader flips V and an original sign model carries V = 1 at its top. MD2 is a left-handed Y-up frame, so a glTF model is mirrored `(x, y, -z)` with reversed winding and conjugated node matrices (Blender `(x, y, z)` to MD2 `(x, z, y)`): the engine's right-handed camera and clockwise culling, the stored face normals, and 800 original sign triangles in 120 models whose text reads left to right and upright only with this chain (`Md2ConventionCorpusTests`).
- **`TgaWriter`** writes the variant every shipped TGA uses (uncompressed true colour, 24 or 32 bit, bottom-left origin, 26-byte footer): all 155 comparable shipped files are written back byte for byte. What tp.exe's TGA loader accepts beyond that was not traced.
- **`opentpw-kit`** (`source/OpenTPW.ContentKit`, in the solution): `object` (glb to `<name>.MD2`, `textures/*.tga`, `<Name>.sam`, assembled `<Name>.RSE`), `mod` (`opentpw-mod.json` and `objects.json`, checked with the game's rules) and `sprites` (swimmer frames to an ESP/FPC/TPC set), with a sideshow-like settings template modelled on `Puzzle.sam` and a placeholder pool script (guests enter, wait, leave).
- **End to end:** the Blender sample pool (or a hand-built glb) goes through the commands into a mod folder, then through the game's mod pipeline (catalog, `LoadModel`, `ConvertMesh`, `ResolveTexture`, heads, the script in `RideVM`), through a guest rig without game data, and, with game data, through the M3 gate: the pool is bought, built, queued and ridden by guests in a headless Jungle park.
- **Found on the way:** a ride script that uses `HUSH`/`HOP` needs `.stack` of at least its capacity, because the header's stack size is the heap size (documented in RSE-SCRIPTS.md).

Not verified: tp.exe's acceptance of authored files, the renderer's draw of a converted model (the placement entity needs a GPU), a sideshow-category object in a park (the gate places rides only).
