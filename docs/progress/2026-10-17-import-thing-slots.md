## An imported original save keeps the slots of the things it does not rebuild (October 17, 2026)

tp.exe's load (`0x518D43`) keeps every saved thing in its slot and rebuilds the free list from the slots the save leaves unused, so the next thing built takes the lowest unused id whatever happens to the saved things later. OpenTPW used to free the slot of a saved thing it did not rebuild (a guest in a state the import drops, an object that did not resolve, a staff member nobody employs), so the next thing took that slot last in, first out and every later id differed from the original's.

- **Placeholders** (`ThingPool.Hold`, `OriginalThingSlots.HoldUnbuilt`): such a slot stays used, with its saved model and its place in the used list, as a placeholder that nothing names, simulates or frees; a destroy request for it changes nothing. After the Easymode import the free list is the original's and the next allocated id is 43 (`OriginalThingSlotsTests`); on a copy of that save with four dropped guests, an unresolved object and an unemployed staff member the next ids are still 43, 44, 45, as the original's load gives them. The Easymode import itself rebuilds all 42 things, so no pinned digest moves.
- **OpenTPW's own save** keeps the placeholders next to the exact free list and the waiting destroy requests (`ThingPoolSnapshot.Held`, optional, validated: a placeholder is a used slot no thing names). The exact free list is split out of WALK-010 as `[EXT:resume-exact-thing-pool]`: the original's save format drops it, an OpenTPW save keeps it so a resumed park continues exactly as the live one. WALK-010 now reads: what the original builds that OpenTPW does not takes no slot, a placeholder never runs on or is destroyed, the destroy requests of a turn come in OpenTPW's update order, the guests' histories hold the script world's attraction ids.
- **Inventory** (docs/SAVE-THINGS.md): for Easymode, the only shipped save, every saved class with its constructor, count, Info.Id and the open ID that covers each gap; and, read through `OPENTPW_TPWS_SAVES`, the eleven private saves: seven parks of five fixed items and one to four guests each, only the two fantasy saves hold a placeholder (guest 39, state 20), none holds a coaster or a track ride (SAVE-920 to SAVE-923 still lack a coaster save), and the four `restart.INTS` do not read through `Import` yet (a calendar and an attraction history ring in their initial state). All 14 attractions, 13 guests and 5 staff members are rebuilt (with the SAVE-006, SAVE-002 and SAVE-004 gaps); the weather, park analyser, tag system, mechanic HQ and UI message receiver things (5 of 42) import nothing and are only bundled in SAVE-010, which needs a per-class split once any of them has a counterpart.
