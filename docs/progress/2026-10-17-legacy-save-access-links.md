## Old saves get the entrance and exit link bytes at load, and a refused stand-point search is the original's dismissal (October 17, 2026)

A park resumed from an OpenTPW save made before an imported park's entrance and exit cells took their saved link byte (#303) holds those cells without the byte, so the edge test `0x4D8750` refused a called guest's last walk into the stand point and OpenTPW kept a route walk where tp.exe dismisses the guest. That fallback is gone and the byte is laid at load instead (WALK-006 retired).

- **Repair at load** (`[EXT:legacy-save-access-links]`, user-approved 2026-10-17): when a park is resumed, `ObjectAccessCells.RepairMissingLinks` gives every ride or shop entrance and exit cell that holds no link bit the byte a placement would lay, through the same writers: the entrance's own bit and queue link toward its queue cell (`0x522700`, `0x5227E0`), and the path writer `0x5348D0` in mode 1 from the outside path cell, which reaches the type-9 or type-10 cell along its queue link (`0x5297BD`, `0x52989A`, `0x529A58`). A cell that already holds a bit is not written to, and neither is a cell whose outside cell is no longer the one the placement laid, so saves holding correct bytes load unchanged. The original needs no repair: its saves always hold the byte (cell serializer `0x4D0B30`).
- **A refused search** (`0x4FFFF0`): the log line "the player has removed the path from under me and I can no longer get into object", the called slot released (`0x4E0AC0`), the guest unlinked (`0x4DDD20`) and dismissed (`0x5012F0`) with no thought, as a refused queue walk already did.
- **Kept**: `[EXT:legacy-save-route-walk]` still covers a route walk restored mid-walk from an even older save (and a guest off the grid); its text no longer cites WALK-006.
- **Tests**: `ObjectAccessCellsTests` strips the bytes of a saved layout and checks the repair equals a fresh placement's bytes, leaves present bytes alone (the cell map's version does not move) and skips a removed outside cell; `ObjectAccessCellsTests` also resumes an old save through the level's own resume branch (`Level.ConnectObjectsToGuests`) and has a called guest walk in; `QueueStandWalkTests` checks that a repaired entrance lets the called guest walk in through the search and that a refused search dismisses the guest.

- **Harnesses**: a ride or shop registered without a placement (the M3 gate, the developer prototype ride `[EXT:developer-prototype]`, and the test rigs of `QueueTests`, `GuestSnapshotTests`, `GuestTests` and the asset tests) had leaned on the route-walk fallback because no entrance cell was laid for the search; they now lay it with `ObjectAccessCells.LayStandCell`, as a placement does. The prototype takes the cell back when it is removed (`ObjectAccessCells.ClearStandCell`, which unlinks it as the cell clear `0x5367A0` does and skips a cell an object owns), and a prototype saved before the build laid it gets the cell at resume.

**Determinism pins**: none moves. The full suite with game data (0 failed) and the smokes (`--smoke-test` sandbox and Jungle, `--park-resume-smoke` capture and restore) pass; a save that already holds correct bytes is not written to, so a resumed park's cell map and hash are unchanged.
