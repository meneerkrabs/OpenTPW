## MD2 model writer and authoring API (October 17, 2026)

- **Writer** (`ModelFileWriter`, `ModelLayout`): a version 221.203 geometry member is written back from a `ModelFile` read with `captureLayout: true`, **byte for byte for all 838 geometry members** of the local corpus (`Md2WriterCorpusTests`; the 1,278 animation members are out of scope and not written). The layout keeps the header as read, the region and per-mesh offsets, node name offsets and sibling order, and the 28 members' non-zero unreferenced runs (found by writing the model and marking which bytes a structure touched, so a field the reader dropped fails the roundtrip). A model read without a layout is written with a planned one; all 838 original models read back field-equal from it.
- **Builder** (`ModelBuilder`): nodes with a hierarchy and transforms, meshes of textured materials, texture names resolved as `<archive>/textures/<name>`, wrap/clamp slot flags (0x10/0x20), and head records (flag 0x80, types 0xB1/0xF1, ids from 1) on nodes for a ride script's ADDHEAD. Tests need no game data: a two-node model with a textured quad and two head records reads back with every field and the head lookup finds both ids; a built model loads as a mod object through the catalog and `ObjectAssets`.
- **Unverified**: the defaults for fields of unknown meaning (header words, flags, node types, bounds) are the commonest corpus values and the planned layout is not the exporter's; tp.exe has not been run on a written model. Table in docs/MD2-MODELS.md, "Writing and authoring".
