## MD2 model writer and authoring API (October 17, 2026)

- **Writer** (`ModelFileWriter`, `ModelLayout`): a version 221.203 geometry member is written back from a `ModelFile` read with `captureLayout: true`, **byte for byte for all 838 geometry members** of the local corpus (`Md2WriterCorpusTests`; the 1,278 animation members are out of scope and not written). The layout keeps the header as read, the region and per-mesh offsets, node name offsets and attribute data offsets; the header words of unknown meaning and the sibling order live in the model (`HeaderOpaque`, `ModelNode.FirstChildIndex`/`NextSiblingIndex`), so planned layouts keep them. Bytes no field accounts for are kept as reported `Gaps` of a captured layout (a last resort); a layout is used only while the model keeps the shape it was captured for. A model read without a layout is written with a planned one; all 838 original models read back field-equal from it.
- **Attribute data blocks (review fix).** The 28 members' non-zero "gap" runs were not unreferenced: every attribute record with type flag 0x40 points at a 16-byte block (`u32` and three floats; 248 of 248 records, none without the flag), and the high 16 bits of its word are the distance back to a second 16-byte position entry (126 records; the entries the first review pass still saw as gaps in 12 members). Both are decoded (`ModelAttributeData`, `Position`), placed and pointer-fixed by the writer in both layouts, and no corpus member needs gap bytes any more.
- **Builder** (`ModelBuilder`): nodes with a hierarchy and transforms, meshes of textured materials, texture names resolved as `<archive>/textures/<name>`, wrap/clamp slot flags (0x10/0x20), and head records (flag 0x80, default type 0xB1, ids from 1; flag 0x40 types need their data block) on nodes for a ride script's ADDHEAD. Tests need no game data: a two-node model with a textured quad and two head records reads back with every field and the head lookup finds both ids; a built model loads as a mod object through the catalog and `ObjectAssets`.
- **Unverified**: the defaults for fields of unknown meaning (header words, flags, node types, bounds) are the commonest corpus values and the planned layout is not the exporter's; tp.exe has not been run on a written model. Table in docs/MD2-MODELS.md, "Writing and authoring".
