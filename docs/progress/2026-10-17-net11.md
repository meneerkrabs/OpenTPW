## .NET 11 builds and passes everything on RC2, with no pin change and no measurable speed-up (October 17, 2026)

Every project now targets `net11.0` (the `net8.0` tools were not touched), `global.json` pins SDK `11.0.100-rc.2.26504.105`
with `allowPrerelease`, CI installs that exact version with `actions/setup-dotnet`, and the server image uses
`mcr.microsoft.com/dotnet/{sdk,aspnet}:11.0`. No package reference needed a bump (no `Microsoft.*` runtime-matched packages).
Draft only: .NET 11 is a release candidate (GA expected 2026-11-10); the decision is in the PR description.

- **Correctness.** The full suite with game data (5842 passed, 141 skipped, 0 failed) is identical to the .NET 10 run of origin/main (4db73c11).
  No determinism pin changed and none was re-pinned. The M3 gate (240 simulated minutes) and the M4 gate (Jungle) print the same
  output on .NET 10 and .NET 11 (same guest and gate state hashes, same verdicts). The five native smokes pass. In the browser the
  texture hash `1CC5AEB033691043` and the simulation hash `0B45FAA2ED526C78` are identical on all four builds (Mono interpreter and AOT, net10 and net11).
- **What broke.** Nothing in the code. One tooling regression: the RC2 SDK breaks restore and `deps.json` generation when the
  checkout is reached through a symlinked path (macOS `/tmp` is `/private/tmp`): project references are missing from `OpenTPW.deps.json`,
  so the setup tests that start the game as a child process fail with "Could not load OpenTPW.Common". Working from the physical
  path (`/private/tmp/...`) is fine; .NET 10 SDK is not affected. Linux CI is not affected.
- **Browser.** `Microsoft.NET.Sdk.WebAssembly` still uses Mono on .NET 11 RC2 by default; the `wasm-tools` workload installs for it and
  both the interpreter and AOT publish work with the existing project file. `-p:UseMonoRuntime=false` (CoreCLR on WebAssembly) publishes
  a smaller bundle (29.8 MB raw, 12.3 MB Brotli, interpreter-style) but the page never reached its first frame in 600 s, so it is not usable yet.
- **Speed.** Medians of 3 alternating runs, same machine, one slot, `.NET 10.0.401` against `11.0.100-rc.2`; the machine was shared, so
  CPU time (user) is the steadier column. See the table in the pull request. In short: native CPU is within noise (M3 +3.7 %,
  M4 -1.5 %, test suite user time -3 %), browser interpreter is 6-14 % faster in several measures, browser AOT is not faster and
  the AOT bundle is 2.9 % larger (Brotli).
