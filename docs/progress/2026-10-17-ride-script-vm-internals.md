## Ride-script VM internals as tp.exe has them (October 17, 2026)

The script interpreter's own state now follows tp.exe (interpreter `0x551CB0`, jump table `0x5567D8`, scheduler pass `0x5516B0`), read in the assembly:

- **Slice and critical flag**: the pass clears the critical flag at every slice start (`0x551701`) and counts the slice budget (the header time slice) down per instruction only while the flag is 0 (`0x551724`..`0x551730`). `CRIT_LOCK` (`0x551D44`) sets it, `CRIT_UNLOCK` (`0x551D59`) clears it and zeroes the budget, so it always ends the slice (the VM used to keep going). The flag has no reader outside the slice loop: the bridge's two "script inside `CRIT_LOCK`" gates (the host step and the presentation at the stand point) had no original counterpart and are gone; the 100,000-instruction slice guard stays as `[EXT:crit-slice-guard]`.
- **TURBO** (`0x5542B9`) stores the low byte of the raw operand word in the script's TURBO byte (`RideVM.TurboByte`, in the VM snapshot); it is no longer a game effect. The byte selects the slice cadence in the pass (`0x5516E1`), which is a separate change.
- **HUSH/HOP** (`0x553D25`, `0x553DAA`) are not visitor operations: they push to and pop (LIFO) from a per-script array of the header stack size that JSR/RETURN use from the other end (`0x5539A9`, `0x553A32`) with no collision check. A full HUSH and an empty HOP do nothing (the original's assert is a bare `ret`, `0x5DA3C0`); a full JSR still jumps without pushing (it faulted before). The corpus's 39 `HUSH VAR_LETMEON` / 39 `HOP` pairs hand the guest ids back newest first; the bridge no longer boards on HUSH nor answers HOP with "first boarded guest not yet hopped": the guest boards when the script consumes `VAR_LETMEON` (host step) or through WALKON/BOUNCE, and leaves through `VAR_LETMEOFF`.
- **LIMBO family** (`0x554DE5`, `0x554EF0`, `0x554F74`, `0x555012`, `0x555045`) is a per-script table of header-limbo-size `{value, expiry}` slots kept by the VM (in its snapshot and, once used, its canonical hash): LIMBO stores in the first slot whose value is 0 with expiry `clock + seconds x 1000` (result 1, 0 when full); UNLIMBO releases the first occupied slot with expiry strictly below the clock (signed 32-bit) and clears it in place; FORCEUNLIMBO needs a variable destination; INLIMBO is the count, LIMBOSPACE size minus count. The bridge's limbo list, its `<=` expiry, `RemoveAt` compaction and the "boards on LIMBO" rule are gone.
- **New handlers** from tp.exe: `PUSH` (`0x553C1E`), `POP` (`0x553CBA`, one operand where the upstream notes say none), `SETLV` (`0x551E19`) and `DBGMSG` (`0x554243`); none occurs in either corpus. The ride lights, `EVENT_EXT` and `GETCUSTPTCLCODE` stay unimplemented (game effects, no corpus use), as does `END`.

**Pinned digests move** (docs/DETERMINISM.md): the fixed synthetic run `0x3DA16AED71E2F1E4` -> `0x188C45B21C1E15E8` (on top of the arrival walk), `WorldStateHash.SchemaVersion` 20 -> 21 (slices end at `CRIT_UNLOCK`, the critical flag no longer survives a slice, the bridge's hopped and limbo lists leave its digest, and the digest hashes the shared array's raw words). No other pin moved.

**Saves**: the VM snapshot gains `Stack`/`StackPointer`/`HeapCount`, `LimboValues`/`LimboExpiries`/`LimboCount` and `TurboByte`; a snapshot with the old `CallStack` still loads (laid out top-down in the array, as code-word offsets with the return tag, which is what JSR stores). The bridge snapshot keeps its `Hopped` and `Limbo` arrays for the file format but writes them empty and marks itself `VmOwnsHeapAndLimbo`. Older saves are migrated on load: the riders HOP had not returned (boarded order, minus the bounce and limbo holds) go into the script's heap so HOP returns them in the old order, and the old limbo list moves into the script's table with its deadlines converted to the scheduler clock; a rider that does not fit the heap of a script that issues HOP is released at the first host step (its `VAR_ONRIDE` share is given back). Return words are the original's code-word offsets, so a script's HOP/POP of a JSR slot sees what the original shows. The host step now marks a taken guest aboard before it processes `VAR_LETMEOFF`, so a guest taken and handed over within one slice is released.

Still open: the slice cadence (a script runs its slice only on the passes its TURBO byte and id select), the ride lights and `EVENT_EXT`/`GETCUSTPTCLCODE`, and the script destruction `END` performs at the end of a pass.
