## DIPMUSIC ducks the music, SETREVERB has a reader, and the unused opcodes no longer fault (October 17, 2026)

Follow-up of the RSE operand round (#365): the three opcode groups that still differed from tp.exe.

- **DIPMUSIC** now acts. The opcode stores its operand's low byte at script +0xB9 and the operand's low word as the global duck request (`0x803AD0`, `0x51E710`); the sound service (`0x51BD70`) sends the music channel's volume as 0 while the word is non-zero (`0x51BE5A`, and `0x51BDC2` in the branch where speech lowers the others) and leaves the other channels alone. A script that ends with its byte set writes the request 0 again (`0x558513`). OpenTPW: `RideVM.MusicDuckByte` (in the snapshot, not hashed), `GameAudio.SetMusicDuck` and `AudioMixer.MusicDuckRequest`; `GameAudio.LeavePark` clears it. `Gates.RSE` runs in OpenTPW, so the end-of-park gate command now silences the park music; `End.RSE` is still not created (RIDES-019). That the duck channel is the music one is medium confidence (options order and the opcode's name).
- **SETREVERB** has a reader after all: the main loop's `0x55A470` (the earlier search stopped inside the script module). While the player rides a ride it takes the ride's root script level (non-zero, 0 or more), otherwise the default 0, and `0x51C8D0` holds the preset and sends it only on a change; the mixer fetches the `SndReverb.map` record (`0x6C5D20`, 15 of 32 entries) and hands it to the device as an EAX 2.0 listener property set (`0x6C46B0`) or to the second backend (QMixer.dll exports `QSWaveMixSetReverb*`). Built: `RideVM.ReverbLevel`, `ReverbSelector`, `GameAudio.SelectReverb` and the `SndReverbMap` format. The reverb DSP itself is not reproduced: new `APPROX:AUDIO-039`.
- **EVENT_EXT** (`0x552707`) is EVENT with a control operand (particle types 1-2 apply a control other than 1000, the sounds ignore it), built on the EVENT path. **GETCUSTPTCLCODE** (`0x5563D5`) is a stub in the original that stores 0, built as such. **ENABLELIGHT, DISABLELIGHT, SETLIGHT and COLOURLIGHT** (`0x555C7A`..`0x555D9A`) switch and colour a light dummy (class `0x20000`) of the object's model; no model of the game has one (274 object models checked) and OpenTPW has no per-object dynamic lights, so they read their operands (SETLIGHT has two, where the upstream notes say one) and become unimplemented effects that do not fault: new `APPROX:RIDES-046`. Every named opcode now has a handler, so a script mod using any of them keeps running.

No determinism pin moved: the new script state (duck byte, reverb level) is not hashed and the new effects are presentation only. SETREVERB's effect is no longer recorded as an unimplemented effect (the VM keeps the level).
