## Evening and night: the night frame no longer walks every object, and the cost is measured (October 18, 2026)

Phase N2 of the lights-and-evening plan. The lamp source of `opentpw.evening` walked every placed object on every night frame (one lookup per object); it now keeps a cache of the lamp-bearing objects that is rebuilt only when the park's object set changes
(`ParkObjects.Version` counts placements and removals), so a night frame touches only the lamp bearers, allocates nothing and lights exactly the same lights in the same order. `EveningTests` cover that the cache follows placement and removal, resolves once per rebuild and does not allocate while the set is unchanged.

- **Native**: the lamp source cost per frame falls by a quarter to a half (medians) (6.4 to 3.4 us for the jungle park, 67 to 41 us for a padded 420-object park with 150 lamp lights, 128 to 99 us for 1400 objects and 500 lights, medians on a heavily loaded machine); the frame average at night is inside the run-to-run spread both
  before and after, and the same 3 lights are in view. Numbers and method are in [EVENING.md](../EVENING.md) ("Performance").
- **Browser**: new `--evening night|dusk|day|off` option of `tools/web-perf/run.mjs` (hook `Level.PerfEvening`, a `PerfEvening` export of the web program) measures a second window in the Jungle park. Night against day against the extension off: 59.99 fps in all three, frame p95 2.1, 1.9 and 2.6 ms, main thread 12.4, 11.9 and 13.7 % busy, no long task.
  Night is not slower in the browser, so no shader or lamp-gathering change was made and the GLES shaders stay as generated.
- Still open: hundreds of lamps in the browser (no equivalent of `--debug-evening-lamps` there).
