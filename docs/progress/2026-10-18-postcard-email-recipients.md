## Send postcards to player names and e-mail addresses (October 18, 2026)

Postcards accept mixed player names and e-mail addresses, split on semicolons, commas and newlines. Shared validation keeps player names with spaces and uses the original localized refusal dialog. Player delivery stays in the server Inbox; e-mail uses the existing configured Resend sender with the message and optional PNG attachment. Each recipient sees only their own address. Partial Send All results keep unconfirmed recipients in Outbox and record confirmed subsets in Sent.

Authenticated delivery has persisted per-account and per-address attempt limits, content-bound receipt keys and deterministic inbox delivery ids. Resend retries retain the provider idempotency key and stop when an unconfirmed attempt reaches the 23-hour safety window; successful receipts have a documented 30-day lifetime. The change adds fake-mail loopback, restart, privacy, malformed-recipient, outbox and adapter regression tests and extends the browser package smoke check. Local fidelity/progress checks pass; .NET and browser runtime execution require CI because this cloud environment has no dotnet SDK. No real e-mails, production configuration changes or deployment were performed. See [postcard delivery](../ONLINE.md#postcard-recipients-and-delivery).
