## Rain mood: the weather rule for happiness, thirst and hunger, once per qualifying day (October 18, 2026)

Phase U4 of the umbrellas extension ([UMBRELLAS.md](../UMBRELLAS.md#the-rain-mood-rule-phase-u4)), stacked on the simulation (U2): `opentpw.rain-mood` (1.0.0, off by default, simulation, not in a Theme Park Inc run, listed on the Extensions and mods screen in all eleven languages) brings Theme Park Inc's weather rule (`0x611050`) to Theme Park World parks.

- **The rule.** In rain, storm and snow a guest's happiness, thirst and hunger change by Theme Park Inc's shipped kid row (rain -1, storm -1, snow +1 happiness; snow thirst -1, hunger +1; the heat wave row never applies), an umbrella that is already **open** when the rule starts adds `UmbrellaModifier` (1) to a negative happiness delta (one the same step opens does not: `TPI-EXE:0x611334`, `0x6111E3`, `0x402d8d`), and the meters are clamped to 0..100 as floats. It runs on the guest's own phase after the umbrella step and before the needs step, for every guest in every state; the umbrella transitions of the same original rule stay in the umbrellas extension and run with the rule off.
- **Once per qualifying day** (`[EXT:rain-mood-once-per-day]`). The original writes its day and never reads it, so it hits on every update of a qualifying day; the extension applies the rule once per qualifying day and guest, at the first update with bad weather. The day is the optional saved `Guest.RainMoodDay` (written, validated and hashed only once set, so older saves load and every park without the extension is byte-equal).
- **Measured.** One kid in constant rain for a park week: -2 happiness without an umbrella (days 0 and 4), 0 with an open one; snow +2 either way. The literal rule would hit on 11 updates in that week (6 on the first day).
- **Pins.** Every existing pin is unchanged with the extension off (and the umbrellas pin stays `0xE912E7E5D5B6E612`). New: `RainMoodFixedRunHash` = `0x3697B9094432D152`, `RainMoodWithUmbrellasFixedRunHash` = `0xADEE2FA6AFC2ACE3` (was `0xF599E7E8B09C0FB7` before the modifier read the state at the start of the step); a park saved mid-rain resumes with the same hash. A save records the extension always while it is on in a Theme Park World run; in a Theme Park Inc run, where its gate is off, nothing records it and an export is not refused for it. Theme Park Inc's own rule is not implemented there.
- **Imported guests** (`[EXT:rain-mood-imported-age]`). An imported original guest without a time in the park counts its age for the day gate from the load, so the rule then applies normally every fourth day (optional saved `RainMoodAgeStartTurn`, written only for such a guest while the extension is on, validated, hashed only when set).
- **User-approved (2026-10-18), all three.** `[EXT:rain-mood-extension]` (the extension, off by default), `[EXT:rain-mood-once-per-day]` and `[EXT:rain-mood-imported-age]` (asked directly, answer "Tellen vanaf het laden") are the user's decisions; see the decisions of [UMBRELLAS.md](../UMBRELLAS.md).
