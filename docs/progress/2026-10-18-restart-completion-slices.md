## Restart snapshot completion work (October 18, 2026)

Follow-up to the reviewed sliced restart snapshot: desktop completion now transfers only the completed immutable JSON buffer to a worker for its copy, SHA256 and atomic marker/snapshot writes. Frame updates poll completion; the existing lifecycle drain waits and observes the original exception, preventing a previous park's worker from outliving its replacement. The browser keeps all work on its single thread but separates serialization from bounded 64 KiB copy/hash steps. Its final in-memory writes remain inline. The initial pending marker still uses the existing durable atomic write; the suggestion to weaken that barrier was not adopted without crash-safety evidence.

Tests cover worker completion/failure/draining, exact chunked bytes and a real synthetic `UpgradeCatalogueDefaultsTests` world whose simulation advances between zero-budget restart pumps while its saved entry bytes remain unchanged. Failure logs now distinguish Instant Action's fresh-start fallback from other modes' load-failed response. PARK-SAVES and WEB document the marker and transactional IndexedDB boundary. No RideVM/Animation code or original game media is changed, and no new speedup is claimed. Candidate runtime measurements remain separate from these scheduling/correctness tests.
