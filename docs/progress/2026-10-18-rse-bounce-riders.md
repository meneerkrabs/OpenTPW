## Bounce rides draw their riders as bodies on the ride (October 18, 2026)

- BOUNCESETNODE (`0x5555D9`) and BOUNCESETBASE (`0x555618`) store the node base (script +0x70, 1 at creation) and the base height (+0x6E) on the visitor bridge instead of reaching the unimplemented effect hook. The base height keeps a literal too (sign-extended from 16 bits); the earlier reading that a literal is ignored was wrong. Both values are saved with the ride only when they differ from the creation values and stay out of the canonical hash.
- The reader is the per-frame script pass `0x557AB0`: each occupied BOUNCE slot's rider is the guest's own kid sprite on the node base + slot (class `0x800`), in the run animation, at the larger of the node's height and `(visitor mod 7 + 12) x sin + ride height + base height` (a half-turn sine hump once per speed-scaled second, 4096-entry table `0x4708D0`), turning one heading step per half second; on a broken ride (script variable 7) the rider stands on its node facing the visitor mod 7.
- Corpus finding: only Jelly Bounce sets the node base (3); Bouncy (jungle and space) and Brain Buster keep the creation value 1. All four set the base height once (8, 6, 16, 12) before their first BOUNCE. Jelly's slots 7 to 9 name nodes its model lacks, so those riders are skipped, as in the original.
- `GuestRenderer` draws a rider of a bounce ride from the pose (`BounceRiders`, `FlatRideBounceRiders`) instead of skipping the Using guest. Approximated: the run template's frame interval (HEADS-007, 100 ms guessed) and the slot's node taken from the current base (HEADS-008).
- Tests (`BounceRiderTests`): operand storage and snapshot, the phase and height rule with hand-computed values, the heading rule, and the shipped scripts and models (data tests).
