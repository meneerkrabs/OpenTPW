## Saving no longer fails with a missing economy binding (October 18, 2026)

- A park refused to save with "placed attraction N is missing its economy binding". Building bought the object, put it in the park, ran the placement handlers (guest registration, pool sites, the HUD's tool follow-up), and only then bound it to its economy record, so anything that threw in between left an object standing, paid for, without its binding. `Level.PlaceObject` now takes the object the moment the park registers it and binds it even when a handler, the build effect or the placement cue throws (the error still surfaces, and a warning is logged).
- A park that already lost a binding this way, such as a browser session in progress, saves again: before a save is captured, any placed object the economy knows without a record adopts the unowned record of its own purchase, or gets an uncharged one when none is left, and the log says so. A save of a park without such objects is byte-for-byte what it was, so no determinism pin moves.
