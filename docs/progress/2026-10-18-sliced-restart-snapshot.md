## Restart snapshot serialization across frames (October 18, 2026)

The restart snapshot still captures and validates the live park at its existing start/load boundary, on the game thread. Its detached JSON is now serialized on subsequent updates using the existing `SlicedJsonSerializer` and a 2 ms soft budget. A single serializer step, capture, asset hashing, final byte copy and atomic write can exceed that budget; this is not a hard frame-time guarantee. Restart, park replacement and orderly shutdown drain an unfinished job synchronously, so immediate Restart uses the entry state and an old job cannot write after a replacement.

The previous restart JSON remains in place while a `.pending.json` marker blocks it from being mistaken for the new park. Once serialization finishes, the marker contains the intended JSON's SHA256 before the atomic replacement. A crash before replacement leaves the old file retained but unavailable through Restart; a crash after replacement and before marker cleanup can recover the new file by matching its digest. Files without a marker retain their existing compatibility. A capture failure still removes a stale restart file, as before. Browser storage remains the page's existing transactional IndexedDB mirror; this does not make an unflushed browser frame durable. No original game files are changed.

Separate `restart-assets`, `restart-capture`, `restart-serialize-slice` and `restart-write` profile sections distinguish the remaining costs. This addresses the synchronous serialization boundary, not the entire reported restart-snapshot time. A same-environment candidate measurement is still required before reporting any speedup. The existing historical M5 measurements and this cloud's blocked browser attempt are not candidate results.

Synthetic tests cover exact synchronous/sliced byte equivalence, capture-once behavior, immediate restart, replacement/drain idempotence, interrupted and malformed markers, failure before atomic replacement and recovery after replacement before cleanup. C# execution requires CI on this machine (no .NET SDK); local fidelity/progress checks and all seven browser-harness Node tests pass.
