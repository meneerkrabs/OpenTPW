## Parks started from an original save write their restart snapshot and autosave again (October 18, 2026)

The native front-end and Jungle smokes logged "Restart snapshot not written (Script 4 WAIT4ANIM deadline -1 is not finite and non-negative.)". The cause was not an animation opcode: the import of an original save's script run state (`RideVM.ImportSavedRunState`, the loader at tp.exe 0x5597A0 reads the WAIT4ANIM deadline at script +164) turned a saved deadline that lies behind the saved clock into -1 as a "past" stand-in, and the snapshot validation rejects negative deadlines. Every original save has such scripts (a finished animation wait leaves its deadline in place until the script runs WAIT4ANIM again), so every park started from an original save (front end, Jungle, the shipped saves) failed to capture its script world. That made Restart Park unavailable there, and the periodic autosave and the manual park-resume capture use the same script-world snapshot and validation, so they failed in those parks too.

A deadline that is not ahead of the saved clock now imports as 0 (none). WAIT4ANIM (0x5538EB) treats the two alike: a zero or reached deadline continues and leaves the deadline cleared, so behaviour does not change. The snapshot format and validation are unchanged, and old saves load as before. No determinism pin moves. Regression tests: `SavedRunStateTests.APastWait4AnimDeadlineImportsAsNoneAndTheScriptSnapshotStaysValid` and, with game data, `OriginalParkScriptSnapshotTests.AJungleParkStartedFromItsShippedSaveCapturesItsScriptWorld`.
