## Cheats, phase K1: the park's cheat record, the turn-boundary queue and the cheated mark (October 19, 2026)

- **A park now keeps its cheats** ([CHEATS.md](../CHEATS.md#the-parks-cheat-record-k1)): `ParkCheats` in the park economy holds the original's cheat mode (`CHTS` byte 0, set by `0x4053C0` and never cleared), a
  record of every applied cheat (turn, kind, argument; at most 4,096 entries) and the cheats waiting for the next turn. Every cheat is queued and applied at the start of the next park turn, before the turn's
  thing sweep, in a fixed order of kinds and with no random draw, so a run with the same cheats at the same turns is the same run. The only kind so far is the mode itself; the original's cheats come in K2.
- **Saves and pins.** The park save holds the record only for a park that has cheated or has a cheat waiting, validated on load; every other park keeps its save bytes and its hash, with the new
  `opentpw.cheats` extension on or off (`FixedRunHash` unchanged; `CheatsTests` checks both). The record joins the run hash through the economy digest only when present; no schema version moved.
- **The extension** `opentpw.cheats` is registered, off by default and not yet selectable (it gets its window in K3). It is used-only: a world save records it once the park has used one of its own
  cheats, and such a save needs it to load; a park cheated through the original's cheat mode alone loads without it, as the user decided that mode works with or without the extension.
- **The cheated mark.** The load and continue menus write "(cheated)" after a cheated park's name, in all eleven UI languages, and a cheated park's shared package carries the informational flag
  `cheated`. Exporting, publishing and ranking stay allowed (the user's decision; the original refused with UITEXT 417): the sharing code and the server are unchanged apart from the flag.
