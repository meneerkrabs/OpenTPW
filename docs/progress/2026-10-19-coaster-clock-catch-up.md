## Coaster clock catch-up and the speed setter's replay gate (October 19, 2026)

A coaster's motion tick now takes as its frame time the simulation time since its last motion tick (`CoasterRide.MotionClockLagSeconds`), as tp.exe's `0x43CE20` takes the scaled game clock since its clock word `ctl+0x120` (whole milliseconds × 0.001, no clamp, no substeps). A cut or reopened track (state 1) runs no motion tick (`0x435AC9`), so the first tick after it is completed again catches the whole stretch up in one tick. The fixed steps stand for the original's scaled clock as the substep scheduler maps it: they stop while the park is paused (the game pause `0x4092A0` freezes the clock) and multiply with the game speed. `EXT:coaster-fixed-step` is narrowed to the frame itself: one motion tick per 60 Hz step instead of one per rendered frame, and no zero-time ticks while the clock stands still.

The speed setter `0x43B2B0` (COAST 8 and the slice tail) now has its gate: a changed speed word is skipped when controller bit `0x8000` is set and no layout replay runs (`0x785A2C`). Only the layout replay's coaster speed action (`0x447E30`, action 0x45) sets the bit; OpenTPW runs no layout replay, so `CoasterRide.SpeedSetByReplay` stays clear. The coaster hash and the park-resume save carry the lag and the bit (optional fields); no pin moved.

The substep gate's flag `0x7A1A8C` bit 0 (`SimulationSubstep`, docs/DETERMINISM.md) is now described as what it is: an option bit, set by default (`0xC0E15`), that skips the substep body while the application is inactive (`0x7A1A14` bit 3 clear). The park pause stops the clock (`0x4092A0`), so a paused park runs no substep and its counter stands, as in OpenTPW. Comments and docs only; no behaviour changed.
