## Co-op C1: the command layer for objects and paths (October 19, 2026)

First part of co-op phase C1 ([COOP.md](../COOP.md)). Every edit of objects, paths and queues is now a serializable command (`ParkCommand`) applied through the park's one funnel, `Level.Commands`, before the next simulation tick: the build tool, the Move tool's pick-up and placement, track add-ons, the remove tool, the sell buttons of the object and attraction windows, the path and queue tools' lines and undo, path and queue cell removal, Backspace over a cell, the queue edit click and the developer prototype. The tools keep their own state (the armed entry, the build angle, the line tool's stack); commands carry everything the executor needs, so the same command does the same on every peer. A read-only visit refuses every command, and `IParkCommandRights` is the hook for the host's per-player rights. Commands have a versioned byte form pinned by a schema test, a command log with hash checkpoints (`--record-commands <file>`) and a replay; a scripted build session replays on a twin park with the same world hash after every tick. A static test refuses a direct call of a converted park mutator from the HUD, the screens or the tools and lists the mutators still to convert (economy settings, then the tools). No determinism pin moved. The co-op design decisions the user approved are quoted in COOP.md.
