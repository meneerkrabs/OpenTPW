## Extensions apply at the next park, without a restart (October 19, 2026)

`[EXT:extensions-apply-at-load]`, user-approved 2026-10-19 ("Ook ontbrekende extensie aanzetten"); follows the load dialog of `[EXT:save-extension-switch]`.

- **The Extensions and mods screen.** When only official extensions changed, OK writes `mods.json` as before and the flow applies them without a restart (`GameFlow.ApplyExtensionChoices`): in the lobby at once, so the next park started or loaded uses them ("The changes apply to the next park you start or load. No restart is needed."), and inside a park when it is left or another park is loaded ("... when you leave this park or load another one."); a Restart Park keeps the running park's set. Never while a park simulates (a park started from inside a park while a choice waits is built in one go, as with a waiting language). A failed load switches back, while the old park is still live, and keeps the choice waiting; a choice taken back in the same park leaves nothing waiting.
- **What re-evaluates.** `ModStartup.ApplyExtensions` sets the active set and the official extensions' catalog content roots (pools, umbrellas, winter; the catalog cache is keyed by them) and tells the host; every other reader already takes the set when a park is built (the guest rules and policy, the weather, the pools tool, slides and rows, `PoolGuestSprites`, the umbrella and warm-item renderers, the evening lamps, the snow) or reads the gate on use (the HUD rows, the cheats window, the info window). The browser fetches the pools sprite sets when pools or its guest art come on later. The load dialog and the load list plan against the extensions the next park uses.
- **Still a restart** (in the browser a page reload), documented in MODS.md "When a change applies": community data mods and their inputs (they overlay the original files, strings and catalogs read at startup; script mods are compiled at startup behind the safe-mode marker), the online extension (folders, command-line tools and the lobby button are set up at startup), extensions set on the command line for the run (`--disable-extension`, `--enable-mod`), and switching off an extension an enabled community mod needs or switching on one a refused community mod needs. A change that includes one of these applies wholly at the next start, with the old restart notice.
- **Docs.** MODS.md (screen, "When a change applies"), DETERMINISM.md, POOLS.md, EVENING.md, WEB.md, RUNNING.md, README.md and the website's mods paragraph.
- **Verification.** `ExtensionsApplyAtLoadTests` (the screen's three notices and the community-mod fallback, the lobby applying at once, a park keeping its set until it is left, a load applying the waiting choice and a failed load keeping it, Restart Park keeping the set, the dialog planning against the next set, an in-park start built in one go with the waiting choice and switched back on failure, a choice taken back, the online extension, both command-line options, a mod's dependency and a refused mod's revival needing the next start, the notices in all eleven languages).
