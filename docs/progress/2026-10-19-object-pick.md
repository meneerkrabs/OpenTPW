## A click on a ride's top picks the ride (October 19, 2026)

A player reported that a click on a shop, a facility or a ride sometimes did nothing, or laid a path behind it. The park click selected the object on the cell of the cursor ray's terrain hit, so a click on the visible upper part of a tall object went to the terrain behind it: an empty cell selected nothing, and a press there started the path tool. The cursor point now follows tp.exe's picker `0x45bf90` in full: after the terrain walk the ray walks the park cells from the camera, one cell per pass with the cell at each crossing of the other axis (the edge cells clamped as `0x45cdc0` does); a cell is tested when the cell lookup `0x452ae0` names its owner (an object with a height map) and the ray over the pass reaches down to the height the map gives and up to the model's bounds minimum, and the owner's model is tested with `0x45d090`'s face test (the nodes depth first, a hidden node's faces skipped but not its children, the faces material by material, the first face whose plane hit has an angle sum of at least 6.2821856); the first model met takes the cursor point when it is nearer the camera than the terrain hit (`World/Original/ObjectRayPick.cs`, `World/Objects/ObjectPickModel.cs`, `Level.TryGetGroundHit`). The hovered cell is that point's cell, as `0x45d560` takes it, so the park click, the path tool's start, the build cursor, the hover help, the visitor pick's neighbourhood and the staff tools' mouse point all follow the same pick, in Theme Park World's HUD, Theme Park Inc's and the browser build alike.

The reading also corrects the register: the original's pick sprites are the people's only. The sprite pass's owner search (`0x532bd0`) accepts thing types 1, 4 to 8 and 0x12 (visitors and staff), and the sprite scripts' FRAME op `0x476940` makes a sprite pickable through `0x540b90`; a ride, shop or feature (thing type 3) is opened by the click dispatcher's mode 4 (`0x4879d0` → `0x486920`), which the hover handler `0x486d90` sets for the owner of the hovered cell. UI-027 is retired; RIDES-021 is narrowed to what is not ported: a track tile's second-layer piece instance (the original tests the piece's model there), the members of a grouped instance (`0x447790`), the node state bits `0x20` and `0x8000`, the normal refresh `0x473c30` of vertex-passed nodes and the hover highlight `0x469180` of the hit instance; GUEST-021 keeps only the screen position of the person in hand. The shipped models' material face ranges are often out of the stored face order (489 of 1630 meshes), and the walk follows the ranges as the original does.

Tests (`ObjectRayPickTests`): the walk, the height window, the edge clamp, the face test and an object without a height map, which the walk passes over; the model walk over a built MD2; the reported click on a tall ride's top, which now selects the ride and starts no path, the same click with a terrain-only pick, which starts the path tool behind it, and a click on empty ground, which still starts the path tool; and, with the game data, every shipped model's face order, that all 250 objects have a height map and that 237 of them are met by a vertical line through their footprint. Picking is input only: no world hash, pin or save changes. The HUD, the tools and the visitor pick share one answer per frame (the same ray and objects), and the face test skips the arc cosines of faces whose angle bound already falls short.
