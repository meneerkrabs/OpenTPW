## Every automated run is offscreen (October 19, 2026)

Tests and agents no longer put a window on the developer's display. At the user's request of October 19, 2026 (smoke tests and agent runs on a virtual screen, such as a virtual framebuffer), the native `[EXT:offscreen-automated-runs]` rule now covers the same automated modes as `[EXT:silent-automated-runs]`: besides the smokes, every `--capture-*`, `--perf-*` and `--debug-*` option, `--offscreen`, `--headless`, the gates, the guest reports and `--validate-assets` create a hidden window and render into the offscreen framebuffer, which is the virtual screen on macOS, where there is no Xvfb. Both rules read one list of automated modes (`Game.IsAutomatedRun`), so they cannot drift apart. `--visible` (new, the window's counterpart of `--audible`), `--no-offscreen` and `OPENTPW_OFFSCREEN=0` keep the visible window; sound and window stay separate choices. Interactive starts stay visible, and `--play-movie` is offscreen only as the movie smoke.

Checked on an Apple-silicon Mac: a Jungle capture at the same size and a 60 Hz frame cap is byte-identical offscreen and in a visible window, since captures read the renderer's own textures; `--debug-sim-minutes` with a capture works offscreen (the headless M3 gate opens no window either way and still passes); a `--perf-run` measures as before (60.0 fps paced, about 4.5 ms a frame with `--no-vsync`). Perf runs stay offscreen by default because the baselines in docs/ENGINE-PERFORMANCE.md were taken with `--offscreen`; a visible run follows the display's refresh and macOS throttling and is not comparable. No game logic, timing or pin changed. Details in docs/RUNNING.md.

Review changes: an offscreen run without usable game data now stops with an error instead of opening the setup window visibly; the docs say a `--debug-*` helper needs `--visible` to be seen and that `--visible` keeps an automated run silent.
