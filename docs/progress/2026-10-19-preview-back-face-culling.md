## Buy preview culls back faces (October 19, 2026)

The winter kiosk's roof slopes showed in the buy window's preview as half roof tiles and half pale trim stripes, split along each slope's diagonal. The content was right and the park view never showed it: the preview (`PreviewIcon`) is a painter-sorted CPU projection without a depth buffer and drew back faces too, so the trim underside 0.55 below each slope won over one triangle of the tiles wherever its centroid sorted nearer. The preview now culls back faces as the park's object renderer does (the outward normal is (B - A) x (C - A), the convention `ModelFile` already uses for its normals). That fixes the same fault on the glühwein stall, the brolly shop, the pool objects and many original Theme Park World previews (a survey found back faces painting over front faces in every preview model; none after). `--debug-hud buyitem:<info id>[,<yaw degrees>]` (Debug builds) opens the buy window on one object type's row and holds its preview at a turn, for captures. New tests: `WinterContentTests.EveryWinterShopsBuyPreviewShowsTheRoofTilesOverTheWholeRoofAtEveryTurn` and `PreviewIconResolutionTests.BackFacesAreCulledAsInTheParkSoTheyNeverPaintOverTheFrontFaces`; both fail without the culling. No content, save or determinism pin changed.
