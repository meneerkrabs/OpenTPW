## Buy preview draws back faces first (October 19, 2026)

The winter kiosk's roof slopes showed in the buy window's preview as half roof tiles and half pale trim stripes, split along each slope's diagonal. The content was right and the park view never showed it: the preview (`PreviewIcon`) is a painter-sorted CPU projection without a depth buffer that sorted back faces and front faces together, so the trim underside 0.55 below each slope won over one triangle of the tiles wherever its centroid sorted nearer. The preview now draws the faces turned away from the viewer first and the faces towards it over them, each back to front (the outward normal is (B - A) x (C - A), the convention `ModelFile` already uses for its normals). Both faces are still drawn, as the original draws them (its only Direct3D cull-mode write is D3DCULL_NONE, tp.exe `0x566957`); culling the back faces instead would have removed the ground plates of the space go-kart and water ride previews, which are wound away from the viewer. This fixes the same fault on the glühwein stall, the brolly shop, the pool objects and many original Theme Park World previews. `--debug-hud buyitem:<info id>[,<yaw degrees>]` (Debug builds) opens the buy window on one object type's row and holds its preview at a turn, for captures. New tests: `WinterContentTests.EveryWinterShopsBuyPreviewShowsTheRoofTilesOverTheWholeRoofAtEveryTurn` and `PreviewIconResolutionTests.BothFacesAreDrawnAndTheBackFacesGoFirstSoTheyNeverPaintOverTheFrontFaces`; both fail with the old order. No content, save or determinism pin changed.
