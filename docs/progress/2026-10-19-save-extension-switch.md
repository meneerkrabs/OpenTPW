## Loading a park with other extensions: switch rules, turn content on (October 19, 2026)

`[EXT:save-extension-switch]` and `[EXT:extensions-apply-at-load]`, user-approved 2026-10-19 ("Ook ontbrekende extensie aanzetten"). A park save whose official extensions differ from the active ones no longer has to be refused: the load asks first.

- **Rule-only extensions in either direction.** `opentpw.rain-mood`, `opentpw.winter-weather`, `opentpw.winter-cold`, `opentpw.winter-always` and `opentpw.smarter-guests` (`ParkExtensionSwitch.RuleOnlyExtensionIds`), each checked in its code and save handling: the weather rules leave only per-guest day marks and the weather they shaped, which every build reads with the rule on or off; the smarter guests' own section starts fresh when the extension comes on and loses the extension's state when it goes off or continues in another version (the guest identity, which script mods share and the traits derive from, stays). A switchable save is not listed as "requires mod". The dialog asks "This park was played without X. Continue with X?" (or with/without, or another version), and the park loads under the active set; its next save records that set.
- **Content extensions the park uses.** `opentpw.pools`, `opentpw.umbrellas`, `opentpw.winter` and `opentpw.cheats` (`ParkResumeMods.UsedOnlyExtensionIds`): "This park uses Pools, which is off. Turn Pools on and load the park?". The tick switches the extension on for this run without a restart (`ModStartup.ApplyExtensions`: the gates, the extension's catalog content root and the mods' hooks; everything else reads the set when a park is built), writes it to `mods.json` like the Extensions and mods screen, keeping the other choices, and loads. A failed load switches the extension back (while the old park is still the live one) and writes nothing. In the browser the page fetches the pools sprite sets it skipped at the start (`Page.RequestPoolSprites`, one fetch at a time, files already stored are skipped).
- **Strict as before:** community mods that are missing or have another version or content, script mods in safe mode, `--disable-extension`, a content extension of another version, the cross-edition objects extension, the order of the mods, Theme Park Inc runs, and every replay and check (`ResumePark` without a confirmed switch, `--park-resume-smoke`, the tests, online play and the original-format export). A strict reason anywhere refuses the whole load with the same message as before.
- **Mechanics.** `ParkResumeMods.UnmetItems` gives each unmet reason a kind; `ParkExtensionSwitch.Plan` classifies them, `Apply` rewrites the snapshot's `Mods` (and the smarter guests' section) for the switched set, and the unchanged strict validation then checks the result. `ModSet.WithExtensions` switches official extensions in the order a new start resolves. The dialog (`ExtensionSwitchDialog`) is the original confirm dialog with its texts in all eleven interface languages; the load list, Continue, the automatic checkpoint and the autosave all ask before the enter-park effect.
- **Determinism.** Agreeing sets take the strict path: no pin, save byte or resume test changes. A switched park is a new run from the switch point (DETERMINISM.md, "Switched parks"; MODS.md, "Loading a park with other extensions").
- **Verification.** `SaveExtensionSwitchTests` (rule-only on and off for each of the five, versions, content on for each of the four, mixed switches, every strict case, Theme Park Inc, the order a switched set takes, the content root and host notice, `mods.json` writing, the dialog in the menu and its texts in all languages, the revert of a failed load), the browser's `serialRequests` in `test_web_pool_sprites.mjs`, the front-end smoke's capture of the dialog, and the native park-resume smoke's switch variant (`OPENTPW_SMOKE_POOLS=1 OPENTPW_SMOKE_SWITCH=pools` on the restore phase: pools off, the dialog's tick turns it on, every continuation tick equals the capture's).
