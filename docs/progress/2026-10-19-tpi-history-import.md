## Theme Park Inc prebuilt history import, checked with data (October 19, 2026)

- **Stale with-data assertion.** `ThemeParkIncSaveWorldTests.ImportJoinsSceneRecordsToAttractionsByMeshAndInfoId` still expected `OriginalParkImport.Statistics` to be null for Theme Park Inc. The TPI analyser history import (`SaveThemeParkIncStatistics`, the [TPI analyser histories](../THEME-PARK-INC.md#historical-statistics-and-the-host-start-boundary) slice) deliberately fills it from TPI's own serializer ordinals 14/17/18/19/20 and ring50. That slice was written without a .NET SDK, and CI has no TPI data, so the failure appeared only locally with `OPENTPW_TPI_PATH`.
- **Import kept, test updated.** The importer was right: it uses a separate TPI decoder, never the TPW graph-history offsets. A static re-read of the TPI no-CD `Game.exe` monthly producer `0x5AF220` agrees: 21 rings at stride 0x250, ring 17 fed from a reset counter, ring 18 a float, ring 19 the mean of at most 50 recent stays, ring 20 from `0x5B81F0`. The test now pins the prebuilt's real analyser (thing 5): every selected ring is empty (head -1, not wrapped) with the 144/50 host capacities; unread slots keep the `0xCDCDCDCD` fill as raw words and read as zero; arrivals come from ring 17's `mTemp` (0). TPI ring 12, the TPW arrivals ordinal, holds 2625, so a TPW-ordinal read would fail the test.
- **Scope.** No runtime code changed and no pin moved. CI cannot run this test because it needs the Theme Park Inc data.
