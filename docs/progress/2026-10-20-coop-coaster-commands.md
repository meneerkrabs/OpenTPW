## Co-op: the coaster tool and its panel become commands (October 20, 2026)

The last tool of the co-op command layer ([COOP.md](../COOP.md), "Tools"; `[EXT:online-coop-commands]`): the coaster tool and its panel now hand their writes to the park's command funnel (kinds 90 to 98). The tool's entry closes the ride, gives its controller the tool's state and marks the coaster as being edited, and its exit clears the mark and opens the ride again; both are commands, so every peer keeps guests off a coaster a player edits. Each build click is a command that carries the panel's height and loop edit mode, and a click on the closed circuit's station end completes the track; Backspace takes the last pylon back through its own command. A drag in the coaster panel is a press, one command for each step of the drag (as the panel wrote the pylon each frame) and a release that settles the money; the stack buttons and the demolish button's cut are commands too. The pylon a player is editing is the level's state rather than the panel's, as the employee in hand is. The commands keep the panel's rules: a drag's steps stay within the range its press gave, the loop button's gate holds, and a panel command needs its coaster in the tool. One drag runs on a coaster at a time, as one pointer gives in a game of one: another player's press, a stack swap, the close and the completion wait while a drag runs, and a click that places a pylon, Backspace and the cut release the running drag first, so no drag settles against a track that changed under it. A HUD's follow-up of its own placement (the coaster, track or queue tool a placed ride opens) now runs after the placement's command, so the tool's entry is logged as a command of its own, and a command issued inside another takes that command's player. Single-player play is unchanged: the tool issues each command where it wrote before.

The guard now refuses the coaster builder's writes and the tool state in the tool layer, which includes the coaster panel; only the developer sandbox load stays listed, for C2. `ParkCommandCodecTests` pins the bytes of the nine new kinds and refuses their out-of-range fields, the fuzz test draws them, and `CoasterCommandTests` runs a whole coaster tool session through its commands, builds the same coaster on a twin from the log alone and fuzzes three players' panel commands on a coaster in each state the tool reaches. `ParkToolCommandLevelTests` builds, closes and completes a coaster in the tool on a level and completes the same coaster on a twin.
