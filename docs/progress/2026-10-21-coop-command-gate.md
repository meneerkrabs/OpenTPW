## Co-op: the command funnel's checks before sessions (October 21, 2026)

Two checks the co-op session needs before it streams a host's commands ([COOP.md](../COOP.md), "The command layer"; `[EXT:online-coop-commands]`). A command whose run throws is now a logged rejection that carries the exception, with what it wrote before the throw, so a replay or a peer that throws at the same place stays in step and the game loop goes on. And no command may be issued while a simulation tick runs, since a peer would apply it a tick later: the level marks each tick after its held commands applied, and the tests and a strict developer run (`OPENTPW_STRICT_COMMANDS=1`) throw on an issue inside one, so every code path that does it is found. A game of one is unchanged: it runs such a command at once, as it always did. The coaster tool's rule of one drag per coaster and its conflict rules now carry the plan's `online-coop-claims` label.
