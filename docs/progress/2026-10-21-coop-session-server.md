## Co-op: the server side of shared parks (October 21, 2026)

The first part of building a park together over the network ([ONLINE.md](../ONLINE.md), "Shared parks"; `[EXT:online-coop-session]`): the server now holds shared park sessions on a new binary WebSocket, the co-op socket (server protocol 6), beside the chat. A host starts a session, listed on the open list or reachable by code and invitation only, and up to three guests join with exactly the host's release and the same simulation-changing mods in the same order; a refusal names the difference. The server relays the host's numbered frames to every guest in order and only from the host's current connection, passes messages between members at most once, and keeps the sessions on disk, so members resume after a lost connection or a server restart and hear the last frame the host relayed. Two games of one account never take turns on the socket, a slow reader is cut off and resumes instead of losing messages, and a session ends when its host has been away ten minutes. The host uploads the park a joiner starts from, and only its members download it (`[EXT:online-coop-snapshot-join]`). The game does not use sessions yet.

`CoopProtocolTests` reads back every message and refuses every malformed form; `CoopServerTests` runs sessions of up to four players against a loopback server: frames and messages, refusals, leaves and kicks, two games of one account, a resume after a lost connection and after a restart, a replaced connection that never relays again, a slow guest, the expiry of an absent host, the open list, invitations, account deletion and the join snapshots.
