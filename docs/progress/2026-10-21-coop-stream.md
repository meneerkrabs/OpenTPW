## Co-op: the host's command stream (October 21, 2026)

A shared park's guests now follow the host's park by replaying the host's commands at the host's ticks ([COOP.md](../COOP.md), "The host's command stream"; `[EXT:online-coop-lockstep]`). The host publishes every command its park applies in frames with a horizon and the session digest every park second; a guest runs its ticks only up to that horizon, checks every digest and every command's outcome, and stops with a desync report when one differs. A lost frame is asked for and resent, the host waits for its slowest following guest within three park seconds, a guest that falls silent or far behind no longer holds it, and the host's park holds while its own link is down. The ride scripts read a session clock the host sets with a command, so two machines with different clocks stay equal. In a session the command funnel drops a command applied inside a tick, refuses one issued inside another and keeps a guest's own clicks out of its log. No game starts a stream yet: the level in a session, the join and the screens follow.

`CoopStreamTests` runs a host and two guests as levels of one asset-free park over an in-memory server, through whole frames of random lengths: a build session at every speed ends with equal parks and command logs, and lost frames, cut frames, faults, refused and errored commands, stalled guests, a server restart and different civil clocks are each covered.
