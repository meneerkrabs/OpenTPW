## Textured park surfaces on Direct3D 11 (October 21, 2026)

On some Windows machines every park surface (ground, objects, the advisor) showed one flat colour per face instead of its texture (issue #754).

- **Cause.** `test.shader`, `advisor.shader` and `sprite.shader` passed their varyings in an interface block (`out VS_OUT { ... } vs_out`). Veldrid.SPIRV's HLSL output turns such a block into its own `main()` parameter. The vertex shader's output signature then has `SV_Position` between the flat varyings and the block, which the pixel shader's input signature lacks. Direct3D 11 drivers that link the two stages by register (WARP among them) handed the pixel shader the clip-space position as its texture coordinates. In a park those coordinates select a coarse mip, so each surface showed its texture's average colour. Metal, Vulkan, WebGL and drivers that link by semantic were not affected.
- **Fix.** The three shaders pass the varyings in a `struct` (`out struct VS_OUT`, as the other shaders already do), which keeps both signatures in location order. The browser's precompiled shaders in `content/shaders/web` are regenerated. Nothing else changes: same inputs, same arithmetic, same picture on the other backends.
- **Tests.** `NativeWorldShaderRenderTests` draws the textured shaders on a real backend into an offscreen target: Direct3D 11 on every Windows machine, including the CI runner's WARP adapter, and Metal on macOS with `OPENTPW_NATIVE_SHADER_TESTS=1`. It checks that a checkerboard texture's cells reach the picture, using the engine's compile path, vertex layout, reflected bindings, mip-generated texture, sampler and Material's uniform buffer. Before the fix it failed on WARP for the three shaders and passed for the struct-based `unlit.shader`. A source test forbids varying interface blocks in any shader.
