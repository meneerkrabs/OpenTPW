## Windows x64 and x86 releases ship the pinned SDL 2.32.10 (October 21, 2026)

Refs [#754](https://github.com/meneerkrabs/OpenTPW/issues/754): on Windows x64 the game had almost no sound, only occasional distorted noise. The `win-x64` and `win-x86` zips shipped the `SDL2.dll` from the Veldrid.SDL2 4.8.0 package, which is SDL 2.0.8 (2018); `win-arm64` already shipped SDL release-2.32.10 built from source. The game's mix (S16 stereo, 22050 Hz, queued with `SDL_QueueAudio`) is clean, but SDL 2.0.8's conversion to the WASAPI float 48 kHz device dropped it: a WASAPI loopback recording of v0.8.94 in a Windows 11 VM showed about 225 gaps of ~27 ms in 40 seconds, against 2 with only `SDL2.dll` replaced by the official 2.32.10 build.

- **Build.** The release workflow's `natives` job now builds SDL2 for `win-x64` and `win-x86` on `windows-latest` with `scripts/build-native.py`, from the same pinned SDL source as `win-arm64`, and both publish entries take it. The script now also checks that a Windows `SDL2.dll` carries the pin's FileVersion.
- **One copy.** A library in `native/<rid>/` now replaces the package's native file of the same name in the build (`PreferBuiltNativeLibraries` in `OpenTPW.csproj`), so the output holds exactly one `SDL2.dll` instead of leaving the choice to the SDK's conflict resolution.
- **Guard.** After publishing, `tools/check_release_natives.py` fails the release if a Windows folder does not hold exactly one `SDL2.dll`, built for the runtime's CPU, with a FileVersion no older than the pin; `tools/test_check_release_natives.py` covers it and the workflow wiring.
- **Unchanged.** veldrid-spirv and cimgui stay from their packages on `win-x64`/`win-x86`: those are the same versions as the pins. Linux x64 bundles no SDL2 and uses the system `libSDL2-2.0.so.0`, as before.
