## Co-op: a server that lost frames no longer ends a shared park (October 22, 2026)

The host keeps only the frames its members may still need. A server whose stored frame number fell behind that, so that it asks for a frame no one holds any more, used to end the session. Now the host gets everyone the park again ([COOP.md](../COOP.md), "The host's trimmed frame"; `[EXT:online-coop-snapshot-join]`): it assigns every member a capture past its last frame, and tells the server the frames go on there (server protocol 7), so nobody needs the frames in between. Each member resyncs from its capture without leaving and without counting a failed join. The server never goes back, and only the host can skip. A stale refusal of a frame sent before the skip changes nothing, and a skip lost with the host's connection goes out again when it reconnects. The server also makes this rare: a frame number a deploy stored exactly now holds for the next run only, so a crash later in that run comes back as an unknown number, which the host fills from the frames it still holds; and a game only opens co-op on a server of protocol 7 or later. This is C2c-3; the screens that start a session (C2d) follow.
