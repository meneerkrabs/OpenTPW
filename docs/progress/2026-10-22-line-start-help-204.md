## The kart and water line tool's advisor help 204 (October 22, 2026)

tp.exe posts advisor help 0xCC (204) when the kart or water line tool takes a click while it has no line start. OpenTPW now has the same producer ([TRACKS.md](../TRACKS.md), "Messages"). The producer map had listed 204 as never said, and the restored advice extension posted it as the roller coaster tool started; that restored hint is dropped, as 344's was when its real producer was found.

- **The trace.** The line modes 0xB and 0x10 dispatch to `0x526CB3` (`0x525A1C`). With the start `0x81EDE4`/`0x81EDE8` at −1 the click stores the clicked cell as the start (`0x526D0F`) and as the first corner (`0x52FBD0`, `0x52FBF0`), pushes 0xCC at `0x526D41` and jumps to `0x527629`, the queue tool's post of 0x151: `0x59B590`, `0x5194D0` on `[0x7CF83C]`, `0x59A940`, the body of the help post `0x486B00`. Unlike 0x151 the post tests neither the replay word `0x785A2C` nor the link flag `0x816D60`. The placement presets the start at the station's exit (`0x52A1A0` at `0x525472`) and the track button's switch from the edit tool presets it at the open end (`0x530830`); `SetMode` `0x52F580` keeps both. So the click is reached only after a line closed its circuit with exactly Ctrl held and no queue start pending (`0x8186C0` zero at `0x526F95`, then `0x527146`); the HUD's tool click passes that Ctrl since the queue end fix of the same day.
- **No withdrawal.** Neither `SetMode` withdrawal list names 0xCC (`0x52F245..0x52F326` in `0x52F200`, `0x52F5BF..0x52F6A0` in `0x52F580`), and none of the 57 calls of `0x486B40` and `0x59AA70` does. `ParkHud.ReportCellToolClick` therefore posts 204 at once instead of holding it behind the frame's mode change, so the tool ending before the next frame does not drop it, and the mode change leaves it pending.
- **A refused tile posts nothing and plays no track click.** The click handler tests the refused-ghost latch `0x816D48` before the mode dispatch (`0x524A63`). Without a start the line modes preview the tile under the cursor alone (`0x52453D`: `0x53AAC0` → the ghost routine `0x5370E0`, which sets the latch for a refused tile, `0x537A1B`), and the mode table sends 0xB and 0x10 to `SetMode(0, 0)` (`0x5266A3`). So a click on a refused tile ends the tool before the start's store and its help. `CellBuildTool`'s refused first click, which covered the path and queue modes, now covers the kart and water line modes too, and the HUD's track click 0xCE skips a refused release, which leaves through the latch's mode table (`0x524AB6`) before `0x526CB3` plays it; the old comment that the cue 0xAF does not stop it is corrected (both found in review).
- **Why the first map missed it.** The poster search read the id pushed in each call's own block; 204's push sits ahead of a jump into another post's tail. A byte scan for `push <id>` of each of the other 35 help ids that no post names finds none that leads to `0x59B590`.
- **The port.** `AdvisorToolHelp.TrackLineStart` (204, in `AdvisorToolHelp.All`, so a park that ends withdraws it like the other tool help) is posted by the HUD for a kart or water line click that gives the tool a start it lacked. The inventory row is `help` and `wired` (`content/data/advisor-producers.toml`). `RestoredAdvice` loses its 204 entry, the coaster tool's restored tip and the `TrackRideHelp` constant; its own mode withdrawal keeps the blueprint hint 202 only. The extension now restores 42 lines (thirteen of the first 55 stood down), and the counts in ADVISOR-SCAN.md, LIPS.md (with the ADVISOR-009 row), MODS.md, the README and the website follow: 236 of the 248 messages the original gives are wired and 103 are never said; the README and the website say 235 spoken, since 204 waits for the queue start below. Their figures also take in 344, which was wired before them.
- **What players notice.** With the extension on (the default), the advisor no longer says 204 when the roller coaster tool starts; 204's speech is about laying kart and water tracks, not the coaster tool. The original's moment, the click that sets a start after an exactly-Ctrl close, posts it with the extension on or off. With shipped rides OpenTPW reaches that moment once the queue start below is ported (the user chose this split: the original's moment only, the queue start in its own PR).
- **Still open (next PR).** In tp.exe the queue tool follows a closed circuit only while the placement's queue start `0x8186C0` is pending. Only placements set it, and the first handover uses it up (`0x527056`). OpenTPW opens the queue tool on every close of a ride with a queue, and every shipped kart and water ride has one (`Info.HasQueue 1` in each theme's `Rides.sam`), so with shipped rides the exactly-Ctrl state, and with it 204, is not reached in play yet. In the same handler a line click with a start on a refused ghost ends the tool and lays nothing in tp.exe (the same latch), where OpenTPW lays the line up to the refused tile.
