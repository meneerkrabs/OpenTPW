## A placed ride's queue tool ends the tool whatever its last click held (October 22, 2026)

After a ride with an entrance is placed, the original's queue tool ends the tool at its last click, and nothing comes back, whatever the modifier ([UI.md](../UI.md), "The Move tool" and UI-031). OpenTPW used to arm the build tool again when that click held exactly Ctrl, and for a moved ride that armed an ordinary purchase (research and the balance test included) instead of the Move tool. The question was which mode the original returns to: the Move tool's 0x3b, the build tool's 4, or neither. tp.exe answers neither, and OpenTPW now does the same.

- **The trace.** The queue tool's handler (`0x5271b7..0x527669`) never reads the modifier word. Its last click is a click on the line's start, or a commit that ends the line on a path or queue cell (`0x536100(0x81)`, `0x527517`); both reach `0x5275b1`, which runs `0x52f200(0, 0)` at `0x5275f2`. That call leaves the mode 0 and the angle 0 (`0x52f3b6`), and it installs the default tool (`0x46c6a0`, `0x46c350` at `0x52f46c`), which deletes the build tool object that held mode 4 or 0x3b and the type (`0x46c5a0`). The Move tool's placement takes the same follow-up as the build tool's (`0x52f580(3, 0)` at `0x52529e` and `0x5258e1`). The Ctrl tests at `0x5253b8`, `0x5259e2` and `0x5259f4` belong to the placing click, and the one at `0x527146` keeps a kart or water line tool that has no queue to follow.
- **The port.** `ParkHud` no longer arms anything when the queue tool ends: the queue a placement opened resets the build angle however it ends. The old Ctrl re-arm and its `[BIN:TPW-EXE:0x5253b8 queue end]` claim are gone, and the new evidence is tagged `[BIN:TPW-EXE:0x5275f2 queue end]`.
- **Co-op.** The Move tool can never return after its queue tool, so the command layer's `EndMoveCommand` (issued as the build tool leaves the Move mode, before the queue tool opens) is the original's outcome. It stays where it is ([COOP.md](../COOP.md)).
- **UI-031 narrowed.** Its text now records the queue end, the kart and water line tools' continuation and the angle kept through the queue tool. What remains open is where the original's coaster placement enters its track tool, which OpenTPW placements have a path cell as the queue's start, and whether a tool armed while the queue tool runs keeps an angle that exactly Ctrl kept.
- **Tests.** `ParkToolCommandLevelTests.TheQueueToolAPlacedRideOpensEndsTheToolWhateverItsLastClickHeld` covers the build tool and the Move tool. In each, a ride is placed with exactly Ctrl held, and its queue tool is then ended by clicks through the HUD's own tool click, also holding exactly Ctrl. Afterwards neither tool is armed, the angle is 0, the queue's end issued no command, and no type is carried. A move logs its `EndMoveCommand` right after the placement. Both cases fail on the old code, which armed the build tool. The unit test of the old re-arm is removed.
- An independent Codex check of the tp.exe trace (read-only) reached the same answer with high confidence.
