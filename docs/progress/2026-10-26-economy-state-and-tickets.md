## Economy state and tickets follow tp.exe (October 26, 2026)

Fidelity round 9, package R9-C. It read the ride state word, the player ticket account, the queue and exit tests, the constructor's track word and the x87 control word in tp.exe, and ported what they say.

- **ECON-023, one ride state word.** The economy record and the visitor bridge now share one `RideStateWord` (`+0x19C`: 0 idle, 1 broken down, 4 condemned). The ride update writes it when it reads VAR_BROKEN in state 0 (`0x4E14E0`, state 4 for a life gauge byte of 0), the repair and every opener write `SetState(0)` (`OriginalObjectRuntime.Open`: `0x4DE487`, `0x4DF438`, `0x4DFCB8`, `0x4E003C`, `0x4E01B6`), and the economy, the guests, the object window and the opening guard read it. The guard reads the word, not VAR_BROKEN (`0x4DF290`), and the park points counts-test reads the word too (`0x4DD920`). The saved import state is kept as saved. The park save holds the word as an optional field; an older save derives it from the broken-down flag and the life gauge. The level publishes the entry into state 1 to the economy once, as before. State 2 (a bought upgrade) is still read from the pending level and state 3 from the type, so ECON-023 stays narrowed; the headless breakdown stays `[EXT:headless-economy-breakdown]`.
- **UI-051, the ticket account.** While a park is part of its player's progress, and in Instant Action, the HUD counter and the purchase check read the player's earned tickets less the spent count (`0x5AF5D0`), and a ticket purchase adds its cost to the ledger's spent count and records the item in the player's bought set (`0x4D4AD0` -> `0x5AF740`, `0x5AF780`; the account is skipped only in game type 1, the online visit, `0xFB3B7C`). The older purchases of a park saved before enter the ledger once, by identity, never twice; one the account cannot afford stays the park's own record, so its next copy is paid in cash. The sandbox (no player file), a co-op session and a read-only visit count the park's own tickets; UI-051 stays narrowed to those.
- **ECON-049, the zero front and the exit test.** A queue ride whose entry has no cardinal link bit has no front, and the opening guard and the object window read it as unconnected (`0x4DE040`, `0x4DE130`, `0x4DE4A0`). The object window shows EXIT NOT CONNECTED from the exit test (`0x4DE5A0`, `0x485F60`): the exit cell's link byte, the cell in front of it and the edge test `0x4D8750` in the three other directions. Untyped exits and entrances keep the permissive answer. The sandbox smoke's track rides are placed with their access cells and their queue is ended on a path, as a player does, instead of relying on the permissive answer.
- **ARRIVAL-003 retired.** The attraction constructor stores 1 in the track word `+0x2C` (`0x4DB0DF`) for every ride, and only a track edit writes it: the line tool's walk (`0x524D1B`, `0x52694F`, `0x526BE1`, `0x526F13`) and its clears (`0x5251B8`, `0x5257FB`). The ride's placement walks nothing (`0x529E10`), so OpenTPW's placement walk now builds the station's sections without writing the word: BUMP 5 and the park points counts-test read 1 after the placement, and the controller saves the word as never written. The tool the placement starts is the line tool (`0x52A050`); the track button reads the word (`0x5267F2`) and opens the edit tool on a ride no edit has walked. `[EXT:track-placement-walk]` keeps only the station's sections.
- **ECON-059, narrowed.** The economy runs on one thread (the thread starters, `_beginthread` `0x67E050` from `0x5C8B7C` (the helper `0x5C8B70`, called from `0x5D1C04`, `0x5D219E` and `0x5D22F0`), `0x66EFE8`, `0x6727DA`, `0x6B6102`, `0x6B9F0C`, `0x6BA362` and `0x6D2FCA`, and `_beginthreadex` `0x67F780` from `0x5FBC4E` and `0x632639`, lie in library code), whose control word is `0x7F` after the shipped D3DIM `CreateDevice` (`DDSCL_FPUSETUP` at `0x563914` and `0x563B7A` lets it). The renderer `0x576EC0` restores the word; bit 1 of `0x8BD508` (the extended-precision restore `0x591250`) is set by no writer (initial value `0x3000141` at `0x583555`). The goods cost keeps its single-precision steps and needs no oracle target on that path. The software renderer path (`0x8BD524` = 4, `0x44DD50..0x44DDE9`) creates no D3DIM device and nothing in tp.exe changes the C runtime's 53 bits there, so ECON-059 stays open for it.
- **SAVE-007, narrowed to unknown projects.** The 11 corpus labs are pinned (projects, started and researched counts, effort split, work load, current projects, highest groups and the object controls' agreement). A known saved current project is kept as saved, offered by the picker now or not, as the loader reads it back (`0x504760`; `ParkResearch.SelectAsSaved`, also through the park save). Projects of objects the archives lack, and current project identities absent from their category's reconstructed table, are still dropped and reported. Those cases occur in none of the pinned labs; original continuation evidence or an explicit supported-save scope decision is still required, so the ordinary corpus does not retire that residual.
- **Determinism.** The pinned fixed-run hashes do not move. **Co-op.** The command shapes are unchanged; a shared park keeps spending its own tickets, and a command log that holds a purchase paid from the account replays only with the same account (docs/COOP.md).
- **Tests.** `RideStateWordTests`, `RideStateRulesTests` (the saved word, a condemned ride, an older save), `PlayerTicketWalletTests` (the counter with global, local and secret tickets and a moved global ticket, the spend, the save and load, the older park, a shared park), `ExitConnectedTests`, `TypedQueueFrontTests` (the zero front is unconnected), `BumpControllerTests` (the track word), `OriginalSaveImportCorpusTests.TheElevenCorpusLabsArePinned`.
