## The UI render state: sprite quads, title shadow, ancestors and the texture filters (October 26, 2026)

Fidelity round 9, package D. This read the render state of the original's UI quads and applied what it settled (`0x58A010`, `0x565F90`, `0x565240`, `0x567620`, `0x567A70`, `0x566840`, `0x5817D8`, `0x581841`, `0x58109E`, `0x57A530`, `0x581CD0`, `0x581DB0`).

- **UI-037 retired, the sprite quads' state.** Every quad of the sprite draw `0x58A010` (control text bitmaps, sprites) is submitted with the fixed state word `0x7060556` (`0x58A26C` overwrites the alpha-type state `0x590C40` gave): alpha blend SRCALPHA/INVSRCALPHA, alpha test at `0x10`, depth test and write on, stage 0 colour = texture MODULATE the control colour as diffuse, point filters, clamp. A control colour of (0,0,0,255) therefore draws exact black: `UiColors.OptionText` is (0,0,0,255) instead of the (16,16,48) read off the video. `OriginalStateWord` decodes the state-word bits that are read, with tests for the sprite word, the face states and the inert bit `0x800000`.
- **UI-007 narrowed, the text path and the title shadow.** The text control draws its string once into its bitmap with the text library in mode 0 (`0x6AD790`): every glyph sample of coverage `c` becomes a texel of alpha 17 x `c` with the colour's RGB (class `0xFB1EF0`, blitters `0x6B24B0` and `0x6B21F0`), and the quads blend the control colour with coverage `c / 15`, the alpha test dropping only coverage 0 (`OriginalTextTexel`). The eleven plain text classes (draw `0x48F830`) have no shadow; the one class with a shadow is the title control (constructor `0x49199C`, draw `0x491AB0`): a grey (128,128,128, alpha `0x80`) copy moved by (-2, +2) bitmap pixels, then the white string over it in the same bitmap (texels written, so the shadow shows only where the string has no coverage), modulated by the title colour. OpenTPW's navy shadow under all text stays its own: the report proposes dropping it from plain text and giving titles the original's darker copy.
- **UI-003 narrowed, the ancestors.** A UI model's frame geometry and stored endpoints now use the node's world matrix (local matrix times the parent's, translations kept), as the instance traverser `0x57A530` does. 168 of the 278 `ui.wad` models chain their state frames (depth up to 5) and no child carries a rotation or scale (`UiHierarchyCorpusTests`); the translations cancel in the selected-mesh fit, so every state still draws over the root mesh's place and only the frames' geometric bounds moved. The control rotation of the original draw is not read.
- **UI-004 narrowed.** The UI nodes go through the scene's batcher (`0x576910` marks them with global `0x8BB624`, `0x581CD0`, `0x581DB0`) with state words from their textures' alpha types, so a cut-out interface texture is tested at `0xF0/255` like a world texture; immediate states are drawn depth-tested in file order, blended parts deferred far to near. The UI vertex depth and whether the UI shares the scene's depth buffer are not read, so OpenTPW keeps its painter order.
- **UI-008 narrowed.** `ui.wad` ships `purple_button.wct` but no UI model names it; the PC's labelled buttons are model-backed (`b_login`, `b_dellog`, `b_loantog`, `b_okay`, `b_exit`).
- **COMPAT-010 narrowed.** `[0x785898]` is SPRITESHADOW, not a filter option: its engine flags `0x20000`/`0x40000` are only tested by the scene pass and the sprite flush. The state bits come from the part's mesh flag `0x8000000` (point magnify) and the texture flag `0x100000` (no mip); the preset filter is TEXTUREFILTERING `[0x785878]`.
- **COMPAT-032 narrowed.** The sign placeholders `sign1.wct` and `sign2.wct` are 24-bit without an alpha plane and the sign builder writes no alpha-type bit that was found; how the composed alpha reaches the draw is the open question.
- **Tests.** `OriginalStateWordTests`, `UiHierarchyCorpusTests`, the chained-ancestor case of `UiModelFitTests`, and `ButtonStateFramesAreDrawnOverTheRootMesh` now asserts what is drawn instead of the geometric centres.
