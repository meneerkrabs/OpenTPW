## The UI render state: sprite quads, title shadow, ancestors and the texture filters (October 26, 2026)

Fidelity round 9, package D. This read the render state of the original's UI quads and applied what it settled (`0x58A010`, `0x565F90`, `0x565240`, `0x567620`, `0x567A70`, `0x566840`, `0x5817D8`, `0x581841`, `0x58109E`, `0x57A530`, `0x581CD0`, `0x581DB0`).

- **UI-037 retired, the sprite quads' state.** Every quad of the sprite draw `0x58A010` (control text bitmaps, sprites) is submitted with the fixed state word `0x7060556` (`0x58A26C` overwrites the alpha-type state `0x590C40` gave): alpha blend SRCALPHA/INVSRCALPHA, alpha test at `0x10`, depth test and write on, stage 0 colour = texture MODULATE the control colour as diffuse, point filters, clamp. A control colour of (0,0,0,255) therefore draws exact black: `UiColors.OptionText` is (0,0,0,255) instead of the (16,16,48) read off the video. `OriginalStateWord` decodes the state-word bits that are read, with tests for the sprite word, the face states and the inert bit `0x800000`.
- **UI-007 retired: the text path and the title bitmap ported.** The text control draws its string once into its bitmap with the text library in mode 0 (`0x6AD790`): every glyph sample of coverage `c` becomes a texel of alpha 17 x `c` with the colour's RGB (class `0xFB1EF0`, blitters `0x6B24B0` and `0x6B21F0`), and the quads blend the control colour with coverage `c / 15`, the alpha test dropping only coverage 0 (`OriginalTextTexel`). The eleven plain text classes (draw `0x48F830`) have no shadow, and OpenTPW's navy shadow is gone from every plain text path (labels, buttons, option and spinner rows, text entry, list headers, rows and cells, all HUD text). The title control (constructor `0x491920`, draw `0x491AB0`; window, screen and lobby titles and, through `0x48C150` -> `0x492F60`, the pause menu lines) draws a grey (128,128,128, alpha `0x80`) copy on the rectangle moved by (-2, +2) pixels, then the white string, both modulated by the title colour: `UiBatch.AddTitleText` does the same at the text scale (`UiLabel.Shadow`, `UiMenuItem`, the dialog captions). The title bitmap is composed on the CPU as the original builds it (`UiTitleBitmap`, cached per atlas, layout, copy alpha and scale): both passes are plain texel writes into one cleared bitmap (the copy's texel alpha `17 x floor(c x alpha / 255)` and nothing at level 0, then the string's `17 x c` over it) and one quad blends it modulated by the title colour; above scale 1 the smoothed coverage is used (`[EXT:hidpi-glyphs]`). Theme Park Inc's title class (constructor `0x515DC0`, vtable `0x93C368`, draw `0x515FE0`, blitter `0x899070`; the personnel-file title and the quit caption) draws the same copy with colour alpha `0xC8`. Placement uses the string's own box, not the copy's. The title bitmap is cut off at the control's box as the original's is (`0x48F3D0` -> `0x588940`, box from `[control+0x18..+0x1E]`; the quad at the box's top-left, `0x491AB0`): exact, because every texel depends on its own two writes. The compose cache is also bounded by 16 MB of pixels, a capped smoothing factor fills the empty texels' colour (no dark fringe), and each bitmap owns one `UiTexture`. Plain text is cut off at its control box as well (`0x48F3D0` -> `0x588940`; width and height truncated, `0x48F47B-0x48F4C5`); OpenTPW-authored texts wider than their box opt out (`UiLabel.Unclipped`, `UiButton.Unclipped`): the object window's not-simulated value (`[EXT:strings]`), the online screens' label buttons (`[EXT:ONLINE-UI]`) and the options page's OpenTPW rows (`[EXT:display]`); a smoke scan found no other overflow. A title bitmap is never dropped in the frame that draws it (a frame generation counter; the count and byte budgets may be exceeded for a frame). UI-007 is retired.
- **UI-003 narrowed, the ancestors.** A UI model's frame geometry and stored endpoints now use the node's world matrix (local matrix times the parent's, translations kept), as the instance traverser `0x57A530` does (the root starts as its local matrix times the caller's). 168 of the 278 `ui.wad` models chain their state frames (depth up to 5) and no child carries a rotation or scale (`UiHierarchyCorpusTests`, which also compares every frame's drawn vertices with the old root-pose shortcut); the translations cancel in the selected-mesh fit, so every state still draws over the root mesh's place and only the frames' geometric bounds moved. The window angle was already `DrawFrame`'s turn (`0x476C50`); the original's state-frame selection stays open.
- **UI-004 narrowed.** The UI nodes go through the scene's batcher (`0x576910` sets global `0x8BB624`, which `0x581CD0` reads at `0x581CF6`, `0x581CFF` and `0x581D15`; `0x581DB0`) with state words from their textures' alpha types, so a cut-out interface texture is tested at `0xF0/255` like a world texture; immediate states are drawn depth-tested in file order, blended parts deferred far to near. The UI vertex depth and whether the UI shares the scene's depth buffer are not read, so OpenTPW keeps its painter order.
- **UI-034 retired.** The interface textures take the original's own states: a UI node's parts go through the scene batcher (`0x576910`, `0x581CD0`, `0x581DB0` -> `0x581790` -> `0x590C40`), so a cut-out interface texture is tested at `0xF0/255` like a world texture, read statically (the capture the ID waited for is not needed). State bit `0x800000` (material word bit 2, which no shipped material sets, PR #863) does have a reader, the sort-key override at `0x58109E`, so it would only change a part's draw order.
- **UI-008 narrowed.** `ui.wad` ships `purple_button.wct` but no UI model names it; the PC's labelled buttons are model-backed (`b_login`, `b_dellog`, `b_loantog`, `b_okay`, `b_exit`).
- **COMPAT-010 narrowed.** `[0x785898]` is SPRITESHADOW, not a filter option: its engine flags `0x20000`/`0x40000` are only tested by the scene pass and the sprite flush. The state bits come from the part's mesh flag `0x8000000` (point magnify) and the texture flag `0x100000` (no mip); the preset filter is TEXTUREFILTERING `[0x785878]`.
- **COMPAT-032 narrowed.** The sign placeholders `sign1.wct` and `sign2.wct` are 24-bit without an alpha plane and the sign builder writes no alpha-type bit that was found; how the composed alpha reaches the draw is the open question.
- **Tests.** `OriginalStateWordTests`, `UiHierarchyCorpusTests`, the chained-ancestor case of `UiModelFitTests`, and `ButtonStateFramesAreDrawnOverTheRootMesh` now asserts what is drawn instead of the geometric centres.
