## UI follow-ups: research knob startup, map, modes, fonts, validator pointers, moon, banner, bridge word (October 29, 2026)

Fidelity round 10, package D2 (the follow-ups of package D, PR #894). Every claim was read in tp.exe; the tpw-decomp research only pointed to where to look.

- **UI-064 (retired).** The research window's workload knob is the slider class whose position setter (vtable slot `0x1c` = `0x66b508` -> `0x66b088`) returns before touching the ball when the raw value is unchanged and the mode is not the refresh -2 (`0x66b201`-`0x66b20d`); the constructor `0x66ad6a` starts raw 0 with the ball at the layout's authored top 399 (row of `0xd2d10`), and no message 0x15 reaches the slider after its base constructor (`0x65bffd`). So an opening with raw 0 keeps the ball at 399 instead of the track bottom 634.
- **UI-100 (narrowed).** The path and queue line previews now carry the validator's end flag: code 0xB (`0x535AE5`, `0x535B3D`, flag `0x816D4C`) is answered for the line's last cell when it is an existing path cell (a one-cell line included, so the path tool over a path shows the end pointer, `0x818688`/`0x820AB8`) and for the ride's own queue cell under the queue tool; the pointer switch `0x52F950` orders link, end, then no-place for a refused line (`0x527950`, latch `0x816D48` set at `0x533933`; a queue stopped only by OpenTPW's own length bound is no refusal), then cash. Open: the end pointer of the kart and water track lines (`0x53A1C6`, track chooser `0x539760`), the `0x539FB6` cash flag of a chooser call that does not refuse, and the crosshair art, which is not in the game data.
- **ECON-030 (narrowed).** The loss banner's animator is read to its cadence and clock: `0x65E72D(table, 0x23)` stores the table, the interval and the clock; the frame message 0x1e is sent down the window tree by the per-frame update `0x658F6C` (called from `0x48A5DF`), `0x65C357` hands it to the stepper `0x65E9A4`, which runs a step when more than 35 ms have passed on `timeGetTime` (`0x65968E`). OpenTPW's `UiWindowAnimation` steps once per drawn frame with the same strict rule, so the banner-timing item is closed; what remains is the co-op owner's decision for the loss scene in shared parks.
- **UI-013 (retired).** The pause-menu measure `0x4929F0` is read to its font pick: the line's font slot (0 for the menus; slots 0 and 2 swap while the word at `0x78b538` is `0x40D`, `0x41A850`), the bank word `0x78b534` and the 24-byte font record at index 13 × bank + slot from `0x78b54c` (handle at +0x14), then the box through `0x6AE1C0` (0x4000 wide without the wrap flag). OpenTPW's text layout box matches that measure; which shipped font serves slot 0 per size tier stays `[EXT:ui-font-tier-by-scale]` (the original's four banks follow its fixed screen modes), so nothing is left to approximate.
- **ECON-023 (retired).** The ride update's dispatch `0x4E0E00` reads the whole state word: 0 runs the update (`0x4E14E0`: VAR_BROKEN, SetState(1) or (4)), 1, 2 and 4 run the head step `0x4E0450` and the script dismiss `0x4E1410` and nothing else, 3 returns at once (`0x4E0E3D`). `RideStateWord` now carries the stored 2 and 3 next to the ride update's 0, 1 and 4 (`Stored`, `Current`; the economy's `ObjectState` and `StoredState` read and write it), and `RideVisitorBridge.UpdateAdmission` dispatches on it: an upgrading ride never reads VAR_BROKEN or runs the admission, whatever its script reports (before, the bridge entered state 1 over an upgrade request that had been stored apart). Saves and the pinned hashes are unchanged (the stored part is derived from the type and the pending level on load, as before).
- **UI-047 (narrowed).** The mode objects are one object, `[0x7b05d8]`, which `0x46c350` replaces after the old one's exit and delete: there is no stack. The seven classes `0x6fe980`-`0x6fead0` return the types 7, 3, 1, 5, 6, 8 and 9 and no class returns 4 (the gate's type 4 is dead). Type 3, the tool-mode object (`0x46c580`), is also what the buy window builds for the Buy Land tool (`0x39`, `0x4ac855`), so the HUD's cost line (`0x4a0cdd`) shows it as it shows every build tool: the Buy Land tool's line is the validator's price of the hovered rectangle (`0x532303`, `0x81af4c`; 0 before the first click and where the validator refused before pricing, the tool start clears it, `0x52f087`). Before, the line was hidden there. The Clear Area (`0x3a`) and patrol (`0x36`) hovers store the hidden marker -10000 (`0x523c18`, `0x523d68`), which the refresh hides, so they show nothing, as before. Open: whether the rotate, tilt and stack edit drags of the coaster panel set bit 0 of `0x79c658` as the height drag does, and the commit of a height drag that a button click ends (`0x447032`, in `World/Coasters`, left to the coaster package).
- **UI-107 (narrowed: the moons are drawn).** The sky objects of a level's Standard.sam (`SkyObjects`, at most 16, hallow one moon behind the sky, space two in front; the setup `0x418C30`, the add `0x5850C0`) are drawn as the sky draw `0x5860D0` builds them, its two passes `0x5865B0` (FrontFlag 0, before the clouds) and `0x586C9E` (FrontFlag 1, after the cylinder). The point goes through the sky's clip matrix (the view without its translation times the projection), a quad of half size Size x 0.5 is added round it in clip space (x scaled by the aspect word `0x8BCBCC`, so a screen-aligned square whose size falls with the depth), turned by the camera roll (`0x578700` from the camera matrix `0x87AFF0`, through the 256-entry sine table of `0x591430`), clipped and submitted white (`0x565F90` mode -3); `Sky.TryMoonQuad` builds it (at an internal depth along the same direction, which projects to the same picture) and `moon_oracle.py` replays tp.exe's own run for the goldens of `SkyTests` (finding X40). Only with SKYDETAIL 1 (`0x44DA1C` sets the engine flag `0x400000`; low.sam 0, med.sam and high.sam 1): `RenderQuality.SkyObjects`. A native capture with the sky turned to the moons shows the space level's moon with its craters at the expected size (about 56 pixel radius at 720p) and the hallow moon behind its cloud layers. Open for UI-107: the flag `0x2000000` variants, the flag 8 mode, the page values and state bit `0x1000` of the objects' textures, the fog and far-plane items already listed.
- **UI-086 (left, text narrowed).** Not ported in this package. The cell classes are read (`0x5f2050`: a cell without an object takes 10 (path), 11 (queue) or 12 (unowned land), a track-record cell `0x536450` 9, an object cell the class of its owner thing by `0x4dd4e0` +0x4ac: 0 -> 1, or 8 on an extension or type-0x15 cell that is not type 4; 1 -> 2; 2 -> 3; 3 -> 4, 5, 6 or 7 by the type word +0x32) and each class is shown by a bit of the map object's +0x18 or its +0x1c mode in `0x5f2380`, whose per-class visibility, footprints, neighbour outlines and item dots need the renderer's own pixel passes.
