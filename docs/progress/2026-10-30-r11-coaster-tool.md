## Coaster tool, fidelity round 11 package G (October 30, 2026)

Package G read the coaster tool's open items in tp.exe (REA, `dis.py`, Unicorn-free static reading; the Mac decomp only pointed to the code):

- **COAST-035 (retired)**: the auxiliary dispatcher `0x447a10` is the layout replay's action `0x38` (its only caller is the replayer `0x4045b0` at `0x40463e`; the replayer `0x785a08` rebuilds a downloaded online park from its recorded actions), so OpenTPW, which runs no layout replay, has no counterpart. The controller/definition flag-2 gate is the definition's loop bit: the definition builder `0x42fad0` sets definition `+0` bit 2 when pylon control 1 (the loop pylon) has a mesh (`0x42fd57`), and `0x442cd0`, `0x442d10`, `0x444c00`, `0x444c50`, `0x444c80` and `0x4445b0` test it first. `CoasterBuilder.LoopUnlocked`, `LoopPairPending` and `StartOrResumeLoopPair` apply it. The loop button itself follows the ride's level only (`0x4980D6`, `0x4987f0`), so a coaster without a loop pylon shows and enables it and its selection just picks the build mode (OpenTPW used to hide it, COAST-028).
- **UI-047 (retired)**: bit 0 of `0x79c658` (the HUD cost line's gate for the coaster panel's edit modes, `0x447990`) is written by exactly one instruction, `0x441a5d` in the height handler `0x441a00`; the rotate press sets bit 1 (`0x441edd`), the tilt press bit 2 with `0x2000` (`0x44205b`) and the stack handlers their own bits, so the cost line shows for a height drag only, as OpenTPW did. A button selected during a drag runs the sub-mode's second action through the switch of `0x446fa0`'s deselect path (`0x44700e`; `0x447032` calls `0x441a00` for the height drag; `0x442220` does the same for the build and loop buttons, and the tool's exit `0x447520`), the same commit as the release; `CoasterToolPanel.Select` already ends the drag that way (a test covers it). A move drag is not in that switch (bit `0x100`), which only a keyboard path could reach.
- **COAST-028, the panel's slide (narrowed)**: the tool's entry `0x4988c0` puts the panel window `0x7ca1c8` (built by `0x498790` from table `0x751530` with the handler `0x4982a0`) into the HUD arm (`0x4a25f0(1)`, `0x4a2590`: message `0xb` retracts the panel the arm carries, message 10 slides the new one out), so it uses the same drawer as the camera and message panels (`ArmSlide`, `ArmDrawer.Shift`): the 675 x 274 root ends at left 486, top 1145 (the offset measured from the video, (-372, +232), was this (-373, +229) within a pixel or three). The tool's exit and the arm's retract button slide it in, and another panel that takes the arm ends the tool (the drawer sends the carried panel message `0x1001d8` before a slide out, `0x4a17dc`; `0x4982a0` answers it with the tool's exit). The loop button's model and hover help follow the flume flag at the panel's refresh (`0x4987f0`: `cb_trough` and help `0x134`, else help `0x132`; the table's 565 is replaced).
- **COAST-028, the area's texture (narrowed)**: the placement area's face type `0x11f` (`0x5243a6` -> `0x536100` -> `0x532fc0`) takes the verdict `0x535670(0x1f, 0)` = 2, slot 2 of the dynamic texture table `0x763b38`: `orange.tga`. The register's "not on the PC CD" was wrong: every level's `dynamic.wad` holds `orange.wct` in `textures` and `stexture` (the generic folder has none), so the generated yellow and black checker is gone and `BlueprintMarkers` loads the level's own texture (low-detail set first when it is on). All records of the table carry texture flags 7.
- **COAST-028, the pointer units (narrowed)**: the drag handlers count the pointer in whole pixels of the selected display mode, not of a 1024-wide screen: the mouse handler `0x42a760` stores hiword x * `[0xfaa5c4]` / 2048 and loword y * `[0xfaa5c0]` / 1536 as integers (the words `0x46b600` takes from the screen mode, 160 x 120 up to 2048 x 1536, 640 x 480 by default) and the handlers copy and subtract them (`0x441b00`, `0x4433ad..0x4434e5`). OpenTPW has no display mode, so the HUD hands the tool the pointer scaled to the default 640 x 480 mode with the fraction dropped on every screen (`[EXT:coaster-drag-reference-mode]`, user decision, October 31, 2026).
- **COAST-028 per-frame rebuild and COAST-033 stored half turn (narrowed)**: every edit handler sets the controller's dirty bit (`0x4346c0`), and each frame `0x435a30` rebuilds every dirty controller through `0x43eb70`: the knot pass (which stores the auto-bank, yaw, pitch and the half turn `0x10000000` in the nodes), the sampler, the rating pass `0x43c450` (its train placement `0x43c1f0` included, and its lift marks, node flag `0x800`, on any chain it draws, finished or not) and the collision pass. OpenTPW now refits a finished track's controller on every step of a drag instead of once on the release (`CoasterBuilder.AfterEdit`), draws the lift marks of an unfinished chain and of a track being dragged live (`CoasterRide.ChainWinchSections`; the lift hills show while they are built), and stores the knot pass's results in the nodes at every builder edit (`CoasterBuilder.Revalidate`; a loaded unfinished chain gets them at its first frame, `ImportOriginal`), so an unfinished chain's nodes hold their auto-banks (a tilt drag counts from them). What stays: the build cursor's node takes part in the original's rebuild of an unfinished chain (the last pylon's stored bank and half turn follow the hovered cell), and only the controller of a finished track is rated on every step.
- **COAST-033, the pylon's ground node (narrowed)**: the pylon models are loaded with flag 1 of `0x1013405` (`0x42fcbf` -> `0x4629d0`), so the type loader's ground-vertex count (`0x46a5a0` -> `0x469a80`) picks a ground node (model `+0x2c`; every PC pylon has one with four ground vertices). `0x432df0` conforms it to the terrain for a bottom node (`0x469940` with the descriptor's ground height) and hides it on a stacked node unless the pylon has flag `0x10`, which `0x42ec47` sets from `bDontDisableBaseOnStack` (no PC coaster sets it). `CoasterPylonRig` now conforms the four ground vertices to the cell corners' heights and hides the node on stacked pylons; the part flag only hides its own mesh (`0x57a5e3`, `0x4723f9`), as OpenTPW already did. Left of COAST-033: the build cursor's node taking part in the rebuild of an unfinished chain.
- **Demolish range preview and the move marks (ported)**: while a cut waits for its second end, `0x443340` takes the pylon under the pointer each frame and marks the range with node flag `0x1000000` (`0x444090` sets it on `[low, high)`, `0x444040` clears it): the first end itself takes its neighbours (a loop pair widens by its partner), another pylon takes the range between it and the first end (ordinal 0 standing for the last node, a loop pair's first widening to the node before it and its second to the node after), and no pylon clears it. `0x43f4e0` draws a marked link with the marker variant `[0x7925d0]` (1 = `m_erase`), red when the node is also invalid, and before the crossing marks; the move press (`0x446d50`) marks `[prev, next)` with variant 3 (blue) and the release (`0x445a70`) clears it. OpenTPW holds the range as `CoasterRangeMark` on the ride (presentation only, never in the track or its saves) and draws it through `CoasterRenderer.LinkMarker`.
- **COAST-028, the model pick (narrowed)**: the picker `0x45bf90` hands the model under the pointer to `0x443ee0`, which maps the handle through the table `0x7a4610` to the node. The HUD now tests the cursor ray against the faces drawn for each pylon (`CoasterRenderer.TryPickPylon`, either side), a nearer terrain point or object winning as in the picker; a pointer beside the model picks nothing. A coaster without drawn pylon models (no game data) is still picked by its cell, and a stack's pieces are not tested as a group (`0x447790`).
- **COAST-033 (retired)**: the build cursor's spare node takes part in the original's rebuild of an unfinished chain, so hovering moves the last pylon's stored bank and half turn. The hover is local to each player, so OpenTPW keeps it out of shared state: `[EXT:coaster-cursor-no-node-writes]` (user decision, October 31, 2026). Nothing else of COAST-033 remains.
- **Drag unit (design choice)**: the coaster drags count whole pixels of the original's default 640 x 480 display mode (`0x42a760`: hiword x * `[0xfaa5c4]` / 2048, loword y * `[0xfaa5c0]` / 1536), scaled from the canvas on every screen, because OpenTPW has no display mode: `[EXT:coaster-drag-reference-mode]` (user decision, October 31, 2026).
- **Review round 1**: the move marks match `0x446d50` (the end node has the next ordinal and a null next link, so moving the last pylon marks `[prev, node]`; pinned by a test); a refitted finished track's drag draws its collision and winch results from the controller instead of computing them twice per step; the COAST-028 register text lists only the real residue; the panel's per-frame arrays are gone.
