## Save import remainder (October 31, 2026)

Round 11 package C reads what an original save still holds that OpenTPW did not import (REA, `dis.py`; the Mac decomp only pointed to the code).

- **ARRIVAL-001 (retired)**: the world loader `0x5179C0` reads the cached bus, seaplane and Ferry handles (`+0x1DA72C/E/30`) and the vehicle at work (`+0x1DA72A`) as raw 16-bit words (`0x00517A56..0x00517B8A`), and nothing checks them afterwards. A handle is the thing id of the vehicle object (`0x0051A2F0` stores the created vehicle's handle at `+0x1DA72C + 2 x kind` and at `+0x1DA72A`; the status read `0x0051A690` goes through the thing), so an imported park takes its scheduler together with the vehicle at work: the cached handles must equal the thing ids of the park's own bus, seaplane and Ferry fixed items, and the vehicle at work is the cached one it equals (the Fantasy corpus saves hold a seaplane at work). The vehicle stands at the status its saved script holds. The saved arrival rate, target capacity and gates-open words have no reader in `0x004CF3E0`, `0x004CF5B0` or `0x004CF720`. A handle that names the wrong thing refuses the scheduler import with the reason.
- **COMPAT-007 (retired)**: the secret name's `0x4053C0(1)` posts a message of type `0x15` (`0x40F6D0` builds it, vtable `0x6FD6C8`, type slot `0x405530`) to the message centre `0x788D3C`, which keeps one subscriber list per type (29 lists; subscribe `0x40F9E0` through the accessor `0x415E00`, delivery `0x40FB10`). All 43 subscribe sites of tp.exe (read one by one, the type is the first pushed argument) use the types 1, 2, 5, 7, 8, 0xA to 0xF, 0x11 to 0x14 and 0x17 to 0x1C, never `0x15`, and no other writer of a list exists (the save and load of the lists, `0x40FD60`/`0x40FC80`, only copy them), so the post reaches nobody and nothing needs building. The gate lines of an original save are the park name as saved, blank included (the rename dialog's OK `0x4993E0` tests no emptiness); the online record copies stay `[EXT:online-park-record-copy]`.
- **SAVE-010, camera (narrowed)**: the loader `0x42CEC0` reads zoom, yaw, flags, the required and the saved point and the saved yaw, clears the flags, copies the yaw to the smoothed yaw `0x7909E0` and, while the options page's Rotation toggle (`0x78D912`, `0x4A3480` case `0x1D4C6`) stands on " 90 degs", turns the target yaw to the nearest quarter turn with single-precision arithmetic (`0x42D03F`). `ParkCameraMode.SnapToQuarterTurn` ports it and a loaded park's camera applies it in the 90 degree mode (OpenTPW's default); the 585 rows of the new oracle golden (X48, `camera_snap_golden.py`, tp.exe's own tail run in Unicorn) agree bit for bit. Left: the smoothed yaw's ease from the saved value to the target (OpenTPW's camera turns at once).
- **GUEST-006, the environment table (narrowed)**: the original saves it. The cell manager's serializer `0x4D7EA0` writes a status byte per cell (bit 1 the map cell, bit 2 the track cell, bit 4 the region effect record, set when its ten bytes differ from the default, `0x502470`) and the records the bits name; the region record `0x502490` is five two-byte words in memory order (the grid at `+0x1B1104`, ten bytes a cell), and the loaded things add no row again (their constructor `0x4DB090` does not run). OpenTPW read the extension as raw bytes and rebuilt the grid from its sources. Now the entertainers and guards take the cell their saved `+0xCC` word names (`mLastRecordedMapID`, `0x4F9460`, the cell the pre-updates `0x4D4660` and `0x4D6360` last saw) as their row's cell, the sources spread again as before, and the words the saved grid holds beyond them are a residue that reads with the grid, is never touched by a later add or remove and is written to OpenTPW's own saves (optional `EnvironmentResidue`, validated, absent when empty). On Easymode (250 saved cells, a guard at (39, 28), an entertainer at (47, 25), toilets and cameras) the rebuilt grid equals the saved one in every cell, so the residue is empty there. Left of GUEST-006 for package S: the bits `0x16` of `0x790AB0` and the show row 7 rule.
