## Track layer, walk records and heights (October 31, 2026)

Round 11 package E reads the track layer's open items in tp.exe (REA, `dis.py`; the Mac decomp only pointed to the code). Items are added below as they land.

- **GUEST-013 (retired)**: the staff drop (`0x46CC40`) and the place click (`0x46C8E0`) refuse a cell whose second-layer record is of a track kind: `0x5363F0` follows an extension record (kind 12 or 17, `0x53AD90`) to its parent word and answers the kind test `0x53AD30` (kinds 0xB, 0xD, 0x10, 0x12 and 0x19) on it, and `0x536450` is the same walk for the hoarding kind (a subset). OpenTPW reads the record through the structure type the queue validator already uses (`QueueCellValidator.StructureTypeAt`: the track layer, and the fence post with the three cells beside it), so a path or queue cell over a straight or stub tile, and the cells next to a fence post, no longer take a staff drop. The occupancy refusal of worlds that keep the cells they were given stays `[EXT:staff-drop-occupancy-refusal]`.
- **WALK-005 (retired)**: the edge test `0x4D8750` reads its target's structure record at `0x4D89C3`: `0x5363F0` (kinds 0xB, 0xD, 0x10, 0x12 and 0x19; an extension 0xC or 0x11 answers through its parent word, none when it is 0), then the flag nibble `0x53AD20` of the record `0x4D89E4..0x4D8A0F` takes. The parent word is the cell index plus one, so OpenTPW's parent index 0 (cell (0, 0)) was wrongly read as no parent. The fence is part of the second layer, so a post (kind 25) and the three cells beside it now block a step onto them whatever the walker stands on, unless the post's flag nibble is set (a post at the water); `FenceLayer.TrackRecordFlags`. The types the tests read are the map cell's own (`PrimaryTypeAt`), since the type op `0x538FC0` writes the record's type and never the cell's. Kind 17 has no writer in tp.exe (every caller of the type op passes 12, a tool's type or 0), and the underground link byte `+0x22` is read only while the land tools' flag `0x81B4CC` is set, inside straight-line land routines (`0x532408..0x532622`, `0x532814..0x5328CB`, `0x53AF51..0x53AF60`) that run no walk. `0x5102F0` is the separation neighbour query (WALK-003, retired earlier). Mask 2 stays the camera's alone (`0x42C093`, `0x42C290`, package Q) with its type-9 rule ported.
- **RIDES-018 (retired)**: the placement's per-cell validator is `0x535670` with mode 4 for body cells (the codes `0x204` and `0x104` of `0x532FC0`; entrance and exit footprint cells never reach it as modes 9 and 10). Its branch `0x535BB3..0x535BD0` refuses a cell whose structure record is of a track kind (`0x53AD30`, an extension through its parent) unless the upgrade selection `0x8187F8` is set, so a path or queue cell lying over a straight or stub tile, and the fence post and the cells beside it, now refuse an object body (`Level.ConfigureObjectHooks`, `IsReserved`); the corner and junction tests `0x53AE00`/`0x53AE90` at `0x535BD7` run for a body cell only on a record of no track kind, which holds no arms, and decide the path and queue tools (`QueueCellValidator`). The build tool's enter `0x46D5A0` hands the type's `Bumper.WhichTrackType` to the type setter `0x52F880` only when its `+0x288` (`AddOn.UpgradeType`) is 1 (`0x46D605`), and the queue option `0x52FAB0` answers `Info.HasQueue` only while that selection is 0 (`ObjectCatalogEntry.QueueOptionOnBuild`; every shipped upgrade of kind 1 has no queue, so the data never tells). The placement commit `0x528A70..0x52A047` holds no code that finds or moves a person (its calls are the cell ops `0x532FC0`, `0x5348D0`, `0x53A510`, the owner and link writers, the creation `0x529E10` and the sound `0x51BFC0`), so a guest inside a new footprint keeps its cell and walks out by the edge test, which lets a walker out of a type 4 cell over a path, another type 4 cell or open ground; OpenTPW no longer sets such guests down at a placement (`SetDownOffCells` stays for the access cells the player removes, `[EXT:removable-access-cells]`).
