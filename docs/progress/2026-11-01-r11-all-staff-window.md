## All Staff window (November 1, 2026)

- **The window (tp.exe `0x496620`).** The original's separate All Staff window is ported (`ParkHud.AllStaffWindow.cs`, `AllStaffRoster.cs`): table `0x750e10` (now generated by `tpw_exe_layouts.py`), the five role tabs (cleaners, mechanics, entertainers, guards, scientists; `0x4968be`, the tab is kept for the session in `0x7ca16c`), the five columns (name, current status, monthly wage, skill bar, happiness bar; row adder `0x496320`, template `0x496d20`) and the frame with the tab's role and all-staff average happiness bars (`0x4c9cc0`, `0x4c7cc0`; taken when the window opens and on a tab press only). A header press re-sorts the rows in their current order (selection sort `0x6628f4`, so equal rows keep their place), a new row goes in by the sorted insert (`0x66403b`), the 2000 ms timer rewrites the status, skill and happiness cells in place (mask `0x1a`; the wage stays), a left click opens the employee window (`0x4b6080`), a right click centres the camera on the member and closes the window. The window posts advisor help 285 as it opens and withdraws it as it closes (`0x496ba3`, `0x495f3b`), so 285 is `wired` (blocked 3 to 2, wired 245 to 246).
- **Entries.** The park information, visitors and attractions windows' all-staff buttons, the employee window's (on the member's role with the member selected, `0x4b5dd9`) and the HUD info button open it; the info button now opens the info window that was open last (park information, All Staff, attractions or visitors; `0x4a0810` records it, `0x4a098a` reads it). The S key stays with the host camera and the rest feature window (`0x4b5173`) does not exist here. The window has no delete flow in the original.
- **The hire window's employee view** (`[EXT:staff-employee-view]`) stays until the user decides about it; its comment now says the separate window exists.
