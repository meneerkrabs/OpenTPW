## Map and object windows (November 1, 2026)

Round 11 package I reads the map window, the object window's local gauge and the build preview in tp.exe (REA, `dis.py`, the x86 oracle; the Mac decomp only pointed to the code).

- **UI-086 (narrowed)**: the map window is the original's renderer. The class writer `0x5F2050` and the renderer `0x5F2380` give each cell its class 1 to 12 (paths, queues and unowned land 10 to 12, a fence post (structure type 0x19, `0x536450`) 9, an object cell the class of its owner thing, `0x4DD4E0` +0x4AC), the layer word, staff role and value mode decide what shows, the fills and the outlines (with the cell-width quirk of `0x5F2A94`) follow the cell grid from (15, 42), the sprite items (`0x5F3940`, `0x5F44D0`: six `/2dmap/*sprite.tga` images, colours by kind, the happiness ramp `0x5F09A0`, staff patrol areas) show while their filters hold, the value modes 2 and 3 (`0x4E0860`, `0x4E1E30`) colour the object cells, and the coaster track layer draws ten Bezier samples per pair through the anti-aliased line `0x5EFB10` (ORACLE.md X54, 108 golden cases). The pointer picks the nearest shown item within five pixels (the pick is `0x5F198E..0x5F1A96`; `0x5F2FD0` is the track layer, which the register text had called a priority order) and shows its name. The old host overlays are gone. The track pixels are composed into a CPU map surface with the original's blend (`0x5EFD21`, coverage 0 included) and the surface is baked into one texture whenever a render event changes its inputs, so a frame submits one quad and the dots. Left: the surface format beyond 32 bit (0x5EDAD0, 0x5EE580, 0x5EF040), the sprite size follows the display height in the original (OpenTPW uses the 640 x 480 reference), whether the item colour modulates or replaces, the pointer's click-through, drag pan and camera-centred initial view, the 16 and 24 bit surface blends, and a per-pixel comparison with a capture.
- **UI-024 (retired)**: the object window's local happiness gauge reads the thing's own cell (bytes +5 and +7: the anchor plus the type's `Info.MapOffsetX/Y` rotated by `0x4D9CC0`, `OriginalObject.ThingCell`). Two shipped objects have an offset, `jungle/5x5rck` and `jungle/mammtunn`, both (0, 1); the old comment claimed none did. The preview is the approved `[EXT:preview-icon-cpu-projection]`.
- **UI-026 (narrowed)**: the footprint grid's cell rectangles match `0x4AB1B0` (record `0x754D50`). The preview's vertex lighting is read (`0x57AA10` -> `0x574660` -> `0x5741B0`: ambient plus the scene's directional and point lights per vertex, in the model's space), but which lights the scene holds with the buy window open is not traced (the advisor adds a white directional light of its own, the light script engine adds model lights, and the park's sun in the theme's `Standard.sam` was not tied to a scene light), so the preview stays unlit.
- **Determinism**: no pin changes. The map, the hover text and the thing cell are presentation only; the debug HUD takes `map:layers=,staff=,value=`.
