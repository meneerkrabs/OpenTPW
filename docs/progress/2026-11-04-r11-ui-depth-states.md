## UI depth and render state decoder (November 4, 2026)

UI-004 (narrowed, ported in part). Every vertex of a UI control model ends at depth 0 in tp.exe: the control matrix `0x476C50` stores m22 = 0 (`0x476CBF`; run unpatched, its z row is zero), the control constructor `0x476AD3` flags the model 0x200 so the instance draw adds 0x2000000 to its parts, and `0x579690` maps such a vertex to 0.1 x z = 0. The z of the HUD models' node translations therefore orders nothing, and `UiModel` no longer sorts by it: one part per material in material order, triangles in file order. An item whose texture has an alpha byte is stashed and its triangles take the tie permutation of the original's triangle sort (`0x565490`, same Hoare quicksort as the record sort `0x5829E0`, ORACLE.md X70, `OriginalDepthSort`, 64 tie orders and 60 key sets golden). The batcher `0x581DB0` was run with synthetic parts: one texture node (the key needs slot flag 0x1000, which nothing sets), deferred chain in list order. Left open: the permutation of a frame's stashed items among themselves and the order against the sprite batches (flushed at `0x58A660` before the scene flush `0x582170`), which needs the scene UI list's insertion order.

UI-003 (narrowed, ported in part). The state of a control is the k-th node down the first-child chain (`0x476E80`); a state past the chain selects nothing (`UiModel.TryGetState`; for all 278 models the chain is the old frame list). Which chain index each button state selects stays unread, so the widgets keep the first frame for a missing state.

COMPAT-010 and COMPAT-018 (narrowed). The option names bind through the record table `0x7442C0` (variable `0x785870 + 4 k`, read, no longer inferred); the per-face filter bits, the device's MIN point and the creation-bit source of texture flag 0x100000 are read. The board is packed bottom-up and reduced to A4R4G4B4 unless TEXTURE32 (all shipped presets: 0); OpenTPW keeps 32-bit textures and point-MINFILTER clamped faces unapplied, both waiting for the player's decision.
