## Advisor scan context words (November 5, 2026)

The advisor's scan callbacks that name a thing or a cell now hand it to the speech, so the message tube's locate buttons work for them (UI-025 narrowed, ADVISOR-009 text corrected). tp.exe's lookup `0x59C0A0` zeroes the scan object's word `+4` and dword `+8` once a row is found (`0x59C10F`), then the callback may store its subject: the dirty toilets 86-89 the dirtiest toilet's thing id (`0x4CA220`: newest thing first, strictly greatest 100 minus the condition byte, stored before the filth thresholds so a low filth still leaves it), the unconnected queue 113 and the scary rides 141 their thing ids (`0x4CCB00`, `0x4CCD10`), the big busload 140 the second bus stop's cell word (`0x4D8650` with the flag 1), and the shop lines 238-257 their handle and figure (passing side only, a negative figure as an unchecked word). The speech copies the nonzero ones into the record (`0x59B6CF`) and the tag actions 3 and 4 read them. OpenTPW's `AdvisorScan.ScoreOf` clears the context before every callback, the callbacks store the words, and `AdvisorController.SpeechCheck` returns them with the score; the scan's own record keeps both words 0 as the original's does (`0x59A5FD`). The level names its objects by thing id (`ParkEconomy.ObjectThingId`) because an economy instance id is not a thing id, and `GuestSettings.BusStopB` reads `FixedItemInfo.BusStopB`. The shop helpers now walk the things newest first (the economy ids descending), so the first met of equal figures is the newest, as `0x4CADF0` takes it; before, the oldest was taken. Nothing is saved (the record already keeps the words), no random draw is added and the determinism pin does not move. Left open: a generic locate-cell word of 0 does nothing instead of the original's unclamped jump (UI-025). This is unreachable for big-busload advice with shipped TPW/TPI settings: all name BusStopBPosX/Y, and `0x4D8650` still passes their nonzero packed word `(Y << 7) + X + 1`, not a missing-stop sentinel of 0.
