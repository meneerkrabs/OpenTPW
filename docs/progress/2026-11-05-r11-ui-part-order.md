## UI part order (November 5, 2026)

Round 11 follow-up 1 reads, in tp.exe (REA, the x86 oracle; the Mac decomp only pointed to the code), the order in which UI instances reach the part list that the batcher `0x581DB0` groups, and keeps the draw order as it is.

- **UI-004 (narrowed further, no rendering change)**: showing a control (`0x476BF0`, slot 5 of the control vtables `0x6FEE10`, `0x6FEE38`, `0x6FEE60`) adds its instance through `0x45BD30` (third argument 0: category 0x20, list scene + 0x18) and `0x576410` -> `0x576270`, which puts a model instance (vtable slot 2 answers 2, `0x40F260`) in front of the other instances, so a list is newest first and hiding (`0x45BDD0` -> `0x576540`) unlinks without reordering. The frame draw walks the lists 1 to 6 (`0x576B86`) into the instance draw `0x57A750`, whose parts `0x581CD0` appends in that order: the part list is the scene list, the control shown last first. The batcher's last-to-first walk undoes it, so controls on pages of their own are drawn in show order, which is the call order OpenTPW keeps (now read, no longer assumed); the registry `0x5775D0` is read by nobody and was never the order. Inside one cache page the list order holds (the control shown last first), and one texture is one node at its oldest user's place; which textures share a page is decided by the placement `0x58F190` for the frame's pending textures together with the world's, and the frame's stashed records sort together with the world's (`0x582AD0` -> `0x5829E0`), so neither is ported. On a scratch dump of the Jungle HUD, buy window, staff window and pause menu one page per texture flips no overlapping pair, merging equal textures flips 5 and 7, one page per width class flips 56, 68 and 18 (the HUD panel over its buttons, which the PC v2.0 video contradicts). The register text now names exactly that: the page sharing, the stash order and keys, and the sprite flush of the control text.
- **Oracle**: `ui_scene_oracle.py` runs the real insertion and the real batcher on a frame's shows; `UiSceneOrder` in `test_x86_oracle.py` pins five readings (ORACLE.md X82, section 7.41).
- **Determinism and saves**: no pin moves (presentation only), no save field.
