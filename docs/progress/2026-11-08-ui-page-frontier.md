## UI page-grouping frontier recorded (November 8, 2026)

Documented the orchestration that still stands between the ported pure helpers and a runtime change: the frame driver `0x58F940`, which clears six width-class counters and, when no class has room, resets a texture's working size from its authored size and drops it unplaced from that frame, and the manager `0x58F190` with its page table (`6 x 256` entries), per-class limit/page-count/used arrays, the two distinct paths (merge-and-pack for ordinary textures; for device-dependent ones on device kind 1, shrink-to-fit, optionally one class up, evict the entry's previous occupants, then the whole page), the eviction of a page's previous occupants, the placement sort and the free-share class tests.

Several corrections came out of the review of this note and are worth recording because they change how the ID reads:

- A page is **not** sized from the first non-fitting texture: its size is its width class's own size, 256, 128, 64, 32, 16 or 8 square, from the table at `0x7022E8`, capped at 256 pages per class. The driver's `-1` branch drops the texture unplaced, matching `docs/MD2-MODELS.md`.
- The budget is not a constant: `0x58D400` asks the device (vcall `+8` on `[0x8BD52C]`, `0x58D41B`) and falls back to `[0x8C1620]` or 32 MiB only when that returns zero; the figure funds a 256-byte-page probe whose measured cost becomes the total, and the real per-class budgets are that total times share floats at `+0x187C..+0x1890` that are not traced. `0x58D670` then cascades each class's leftover into the next and returns class 5's into class 0 for a second pass. A page costs `bpp x size^2` with `bpp` from `0x7022D8` indexed by the texture **format** `[0x8BD554]` (not the device kind `[0x8BD524]`), and `(4 x bpp x size^2) / 3` when the alignment gate exceeds 1.
- `+0x10`/`+0x12` are the **authored** size and `+0x14`/`+0x16` the working size the halving rewrites; and `0x58EAE0`'s ordering follows from its comparisons at `0x58EB62`/`0x58EB71`, so it is largest-authored-first.
- `0x58EA20` (the 2x free-share test) is called only from the merge-and-pack path; the device-dependent path uses an inline comparison without the factor.
- `0x590350` writes the page handle into the texture's `+0x1C` (`0x590678`), and `0x58DB0C`'s `0x40/0x80/0x100` are overwritten with `0x10` at `0x58DB34`, so neither is a page-size policy.

Also corrected two allocator notes from the earlier review: the `0x57CED0` comment no longer calls the routine `OriginalDepthSort` (it is a separate integer quicksort that shares the partition structure), and the free array now uses the native capacity of 128 records. No allocator behaviour changes and its goldens still pass. UI-004 stays open; no APPROX/EXT, save field or determinism pin changes.
