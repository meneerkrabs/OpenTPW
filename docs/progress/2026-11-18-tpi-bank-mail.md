## Theme Park Inc bank: the red-month mail (November 18, 2026)

A Theme Park Inc park that stays in the red now says so. The bank's six-months test (`0x5C0C99`) does not itself lose the park, but its event value 2 comes back to the bank as a type-19 message (`0x5C091F`), which posts a 36-byte type-25 notification (`0x435DF0`, record `0x5CEE50`: id 8, group 1, the null tag `0x97`). Exactly one subscriber takes type 25: the tag and mail system (`0x635A72`), whose handler (`0x635D80`) builds a record from it and hands it to the mail window (`0x526CD0`, window procedure `0x526960`). The record carries advice message `0x1A2` — response 749, speech event 869, tag `0x5E`, `TAG_SYSTEM.str` entry 166 — and that entry is the bank's closure letter: it tells the player the banks are forcing the park to close after six months in the red. Dismissing the letter is what loses the park: the letter window's procedure (`0x526960`) calls `0x649E60`, which sets the lost state and opens the "BANKRUPT!" loss window (`0x50AFC0`); OpenTPW does not port that window or the loss yet. Of the other two messages the same builder can carry, id 6 (`0x1A1`, null tag) has no sender and id 7 (`0x1A3`, tag `0x5F`) is the challenge system's lost-challenge mail.

`ParkEconomy` hands the client `ThemeParkIncAdviceMail.RedSixMonths` at each month end where `MonthsInRed` has reached six, and the desktop slice plays its speech from the global catalogue and puts its `TAG_SYSTEM.str` entry on the advice line (the line the forecasts already use; the original lists the mail in its mail window, which OpenTPW does not reproduce). Nothing new is saved: the mail follows `MonthsInRed`, which the save already carries. The same handoff carries `ThemeParkIncAdviceMail.ChallengeLost` (advice `0x1A3`, response 750, speech 870, tag `0x5F`, entry 167 — the second closure letter, this one about failed challenges) once the career firing line is used up: the original starts it at a fixed 5 (`0x74BDD1`), takes one off per lost challenge (`0x5C4857`) and posts the mail on every loss that leaves it at zero or below (`0x5C48B6`), so the fifth loss and each one after it bring the letter. The current slice refuses the challenge system for Theme Park Inc, so that mail only appears once Theme Park Inc challenges run.

Verified: a new economy test walks a park into the red and asserts no mail before six months, the mail on the sixth, its one-time handoff and its return on the next red month, and that a Theme Park World park has none; 342 Theme Park Inc tests pass with the retail data (3 skipped). The native checks live in `tpi_advisor_forecast_oracle.py`, which now also reads the three red-month descriptor rows, their three response rows and the tag-94 caption entry. Nothing was launched and no binary, data or save bytes are included.

The advisor's scoring names `InTheRedSixMonths`, `InTheRedThreeMonths`, `InTheRedMonthLeft` and `Bankrupted` (`0x982598`, `0x98264C`, `0x982700`, `0x9827B4`) sit in a table that no immediate or pointer in the file references, so no consumer of them is traced. The notification's payload constructor has three callers: the bank at `0x5C0969` (id 8, modelled), a window-module path at `0x53530C` (id 8 again, after destroying a window) and the challenge system at `0x5C48DD` (id 7, logging `Lost the challenge!!!`), so id 7 carries the challenge-lost advice message `0x1A3` and nothing builds an id-6 record. Promotions, which raise the line to `FiringLineForRank[n].Limit` (`0x74C450`), are not modelled; the challenge system itself stays outside this slice. The full chain is in `docs/reverse/TPI-BANK-MAIL.md`.

Update (November 21, 2026): the advice-line caption and the unported loss window described above are superseded. The mail now opens the original letter window, and closing it loses the park (see "Theme Park Inc: the \"Game Over\" letter loses the park").
