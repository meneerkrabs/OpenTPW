## Theme Park Inc weather forecast advice (November 18, 2026)

The original rolls the next weather spell in its month handler and posts advice for the rolled kind: heatwave `0x154`, rain `0x157`, storm `0x15B` and snow `0x15A`. Each descriptor row carries response `642/645/649/648`, a speech event (`763/766/769/938`) and a tag whose `TAG_SYSTEM.str` entry is `127/130/156/133`. The four rows share message group 0, and the shipped `Advisor.sam` gives that group its repeat intervals. A second identical forecast is admitted while an earlier one is pending; the descriptor's duplicate limit is 255. On a full queue the original replaces only a strictly lower score and still reports success on a tie.

`ThemeParkIncForecastQueue` ports the eight slots, the per-kind history, the strict score floor, first-slot selection, the consume-then-recheck order and the playback window of the speech's length plus 1000 ms. `ThemeParkIncForecastSettings` reads the score floor and the group's four repeat intervals from the mounted `Advisor/Advisor.sam`; without a mounted file the park simply has no forecast advice, as the original has no advisor without it. The economy posts the spell the month handler returns, at the world tick shifted by two, and the queue is saved as an optional `TpiForecast` payload that the edition validation accepts only in a Theme Park Inc park. The desktop slice ticks the queue on the scene clock, plays the response's speech event from the global `cat_speech` catalogue and shows the caption on a line that holds until the next forecast.

Verified: 10 queue tests including the round trip and the rejection of foreign rows; the economy's month test now asserts that the rolling month posts exactly one forecast and that it survives a save and restore; 81 targeted Theme Park Inc economy, weather, play, language and forecast tests pass with the retail data. All four forecasts were played in a running retail Science park through `--debug-tpi-forecast`, each with exit 0 and no missing caption: heatwave response 642 with speech 763, caption 127 and a 5,758 + 1,000 ms window; rain 645 with speech 766, caption 130 and 5,526 + 1,000 ms; storm 649 with speech 938, caption 156 and 5,909 + 1,000 ms; snow 648 with speech 769, caption 133 and 4,783 + 1,000 ms. The speech came from the global catalogue (1,136 events), and 0 of 18 object scripts stood faulted. The native oracle now replays 28 score cases and the 72 class admissions of the eligibility matrix alongside the descriptor, response, caption, queue and playback cases, and 341 Theme Park Inc tests pass with the retail data (3 skipped).

The eligibility check is now traced. `0x71B7E0` finds the descriptor row by message ID and asks `0x71BDC0` whether that row's class is one the current advice context selects; the oracle patches the heatwave row's class through 0 to 7 in each context and shows that the default mode word admits classes 0 and 2, mode word 1 class 2, mode word 2 classes 1 and 2, mode word 3 class 3, the game object's byte `+0x2E` class 5, `+0x2F` class 7, and the animation word classes 6, 5 and 4 for its variants 0, 1 and 2. The mode word is a four-valued static at `0xC65B80` derived from four bits of the packed option dword at `0xA2CA84` (`0x6A5EF0`, setter `0x6A5FF0`, called from the settings loader); the two bytes belong to the global object at `0xA6E158` and are written from sixteen sites with literal 0 or 1; the animation word at `0xA9D230` belongs to the animation module, which also stops the advisor from taking in advice (`0x718227`) while it is set, as does `+0x2F`. Since the four forecast rows are class 2, they are admissible whenever the mode word is not 3 and none of those contexts is active, which is what `ParkEconomy.TpiForecastEligible` reports for a running Science park. What the game calls those contexts is still not established; the classes they admit are.
