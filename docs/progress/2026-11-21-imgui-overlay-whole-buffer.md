## The ImGui overlay's buffers on Direct3D 11 (November 21, 2026)

The Direct3D 11 dynamic-buffer fix for issue #829 left one writer outside it: the Veldrid.ImGui package's renderer, which draws the editor overlay and the first-run setup wizard. Inside its `Render`, right after `ImGui.Render()`, it wrote each ImGui draw list into its dynamic vertex and index buffers at the list's own offset. Every one of those is a partial write, which Veldrid 4.9 turns into a staging copy into the dynamic buffer on Direct3D 11. Nothing outside the class can reach those writes.

OpenTPW now draws ImGui with its own copy of that renderer, `ImGuiOverlayRenderer` (`source/OpenTPW.ModKit/ImGui`). The copy is Veldrid's v4.8.0 source, the code the 5.72.0 package was built from, kept under its MIT notice. It still reads the package's embedded shaders. Its buffer change copies all of a frame's lists into one contiguous CPU block and uploads that from offset 0 as a single write through `DynamicBufferUpload`. On Direct3D 11 that becomes a whole-buffer `Map(WRITE_DISCARD)`; on Metal, Vulkan and WebGL the byte count is unchanged. The draw calls, their offsets and the projection matrix are unchanged.

One behaviour changes, in the setup wizard only. The package was compiled against ImGui.NET 1.72, so it filled `io.KeyMap` at the old key indices 0..21, which the ImGui.NET 1.87 this repository uses ignores. Compiled here, the same `SetOpenTKKeyMappings` fills the `ImGuiKey` values 1.87 reads (512 and up). In the game this changes nothing: the editor (`Editor.SetKeyMappings`, created right after the renderer) already filled the 1.87 values, so Tab, the arrows and the editing keys already worked in the online panel and the editor's file browser; only the stray writes to indices 0..21 stop. The setup wizard has no editor, so its folder field now gets Tab, the arrows, Backspace, Delete, Enter, Escape and Ctrl+A/C/V/X/Y/Z for the first time. `Editor.SetKeyMappings` is now redundant with the renderer's own mapping and can go in a later cleanup.

`DynamicBufferUpload` moved to `OpenTPW.Common` so the ModKit renderer can use it. The device's backend is now recorded where the device is made (`Renderer.CreateDevice`), for the game and the setup wizard alike; `WholeBufferWrites` reads that record instead of `Global.Device`, so a test that makes a Direct3D 11 device without `Renderer.CreateDevice` gets no widening unless it sets `DynamicBufferUpload.Backend` (as `ImGuiOverlayRendererTests` does). The browser keeps its stub, now named `ImGuiOverlayRenderer` in `DesktopOnly.cs`, and the source contract test covers the copy too.

Verified: `ImGuiOverlayRendererTests` draws two lists, the background band and a foreground rectangle, on a real device and reads them back over two frames. It runs on Direct3D 11 on Windows CI and passed here on Metal. Also checked: `DynamicBufferUploadTests` (now also the package's shader names for every backend), the browser build with and without the determinism pins, and the five native smokes. Not verified: Direct3D 11 on the reporter's NVIDIA driver.
