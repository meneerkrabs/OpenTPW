## The per-draw uniform buffer is 784 bytes (November 21, 2026)

Every material wrote its per-draw uniform block into a 2048-byte dynamic buffer (`Material.ScratchBuffer`, `16 * 128`). Since #969, a partial write into a dynamic buffer on Direct3D 11 is widened to the whole buffer (`DynamicBufferUpload`), so every draw uploaded 2048 bytes there, about seven times the usual 272-byte block. This came up in #969's integration review.

The buffer is now `Material.ScratchBufferBytes`, 784 bytes. That is the largest block a draw uploads, the lit block with all 16 point lights (`LitObjectUniformBuffer`: 272 + 16 x 32). It is also the largest uniform block any shader declares (test, pool-deck and pool-basin; the other shaders declare 236 to 272 bytes), so a bound buffer still covers every block its shader reads. `Material.Set<T>` now refuses a block larger than the buffer instead of writing past it.

`MaterialScratchBufferTests` pins the size to the lit block and its upload size with every light. It also reads every shader's uniform blocks in std140 layout and checks that the largest equals the buffer exactly. Verified: those tests, the material, point-light, shader and dynamic-buffer tests (94 passed; `PointLightTests` now checks the lit upload against `ScratchBufferBytes`), the browser build with and without the determinism pins, and the five native smokes on Metal. No behaviour changes: every block a draw uploads is the same as before.
