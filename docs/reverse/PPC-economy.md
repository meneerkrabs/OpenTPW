# PowerPC economy evidence

2026-10-09. Economy lane; static inspection of the local Feral Mac PEFs.
No original program was run. All addresses below are offsets in expanded
section 0 unless explicitly marked as section 1/data. Raw binary sections,
original assets and disassembly remain outside Git. Mac findings do not
establish the behavior of the Windows patch-2 executable.

The highest-impact finding is that loans use an upfront power expression,
not an amortizing annuity. Calendar time, researcher contributions and wear
also advance on different schedules. The current daily economy aggregation
cannot preserve these independently scheduled operations.

## Loans: ECON-006, ECON-007 and ECON-039

The constructor at `0xcb7a8` fills eight 32-byte loan records. Serialization
at `0xcba54` couples each field address with an actual debug/save label:

| Offset relative to bank object + 32 × loan index | Meaning | Serializer operand |
| --- | --- | --- |
| `+20` | available flag | `0xcbbb4` |
| `+24` | principal offered | `0xcbbd8` |
| `+28` | APR in percent | `0xcbbfc` |
| `+32` | term in months | `0xcbc20` |
| `+36` | monthly repayment | `0xcbc44` |
| `+40` | loan bought | `0xcbc68` |
| `+44` | months repaid | `0xcbc8c` |
| `+48` | lender name index | `0xcbcb0` |

Thus the constructor arithmetic is connected to field meanings, not merely
to an attractive function name. It reads amount/APR/term from the global
balance payload at `+416/+420/+424`, advancing that source by 16 bytes per
offer, and stores those values at the labeled loan offsets.

With principal `P`, percentage APR `A`, and term `N`, the expression is:

`M = trunc_u32(P × pow(1 + A/100, (N/12) × 0.5) / N)`.

The constants are doubles at data `0x5428 = 100`, `0x5420 = 12`,
`0x5418 = 1`, `0x5410 = 0.5`. At `0xcb8bc–0xcb8c8` the constructor
forms the exponent and base; `0xcb8cc` calls C-library `pow` through glue
`0x1c61a4`. It multiplies the result by `P` at `0xcb8e4`, divides by `N`
at `0xcb8e8`, calls conversion helper `0x1c3fbc` at `0xcb8ec`, and
stores `M` at `0xcb8f4`. The conversion helper truncates positive finite
values toward zero, returning zero below zero and saturating at the unsigned
32-bit upper bound. Ordinary SAM loan inputs are far from those bounds.

Derived examples using the actual PC SAM inputs, in offer order:

| Principal | APR | Months | Mac expression monthly | Total installments |
| ---: | ---: | ---: | ---: | ---: |
| 100000 | 20 | 36 | 3651 | 131436 |
| 50000 | 20 | 36 | 1825 | 65700 |
| 25000 | 20 | 36 | 912 | 32832 |
| 10000 | 20 | 36 | 365 | 13140 |
| 18000 | 23 | 24 | 922 | 22128 |
| 30000 | 22 | 30 | 1282 | 38460 |
| 80000 | 18 | 48 | 2320 | 111360 |
| 65000 | 21 | 30 | 2749 | 82470 |

These are mathematical examples, not observed original UI values. At zero
APR the same expression is `floor(P/N)`, agreeing with the existing easy-save
evidence. PC input-file equality does not prove PC arithmetic equality.

The month handler at `0xcc21c` subtracts the same stored `M` from bank balance
for each bought loan (`0xcc2d0–0xcc2e4`) and increments months repaid. It
clears bought and months-repaid flags when the count equals `N`
(`0xcc394–0xcc3bc`). It does not maintain a declining principal balance or
compute monthly APR interest. Message dispatch at `0xcc120` routes message
type 12 to this handler; the calendar creates that message through `0x116488`.

Early payoff at `0xccc78` computes `M × (N - months_repaid)` at
`0xcccc4–0xcccd8`, checks affordability, subtracts that full outstanding
installment total, and clears bought/months-repaid. Applying at `0xcc904`
rejects an already bought loan, then adds the principal and sets bought.
There is no permanent spent-offer flag. Availability still depends on
`0xcc6d0` / `0xcc9e8`, which compare a capacity statistic against outstanding
installments; repaid offers are not necessarily always selectable.

`mProfitThisYear` is explicitly bound to bank `+292` by serializer `0xcbb84`.
Loan acquisition adds principal to the bank/deposit accumulator but cancels
it out of this yearly profit field (`0xcc9b4–0xcc9cc`). Each monthly payment
reduces yearly profit by `floor((M×N - P)/N)`, via `0xcc370–0xcc390`.
Message type 13 resets this field to zero at `0xcc1e4–0xcc1e8`: this is a
calendar-year accumulator, not the last twelve closed months. The early
payoff profit adjustment is especially sensitive: it clears months repaid
before the subsequent profit calculation reads that field. Preserve that
ordering if a Mac behavior mode is implemented; do not silently reinterpret
it as conventional amortization.

Confidence: high for Mac arithmetic and field identities. Removing PC
approximation tags still requires executable/capture evidence for that target.

## Calendar: ECON-001..004

Constructor `0xe3c90` stores `15000` at calendar `+28`; serializer `0xe3d30`
names that field `mFunnySecsPerRealSec`, and labels the timestamp at `+0`
`mFunnyTimeStart`. The initializer `0xe4348` passes
`2000, 1, 1, 0, 0, 0, 0` to `TbTimeStamp::SetTime`.

Conversion `0xe4394` loads the turn counter at game `+0x1da70c` after calling
`0x10a9a4`. It forms the full unsigned 64-bit product of turn and calendar
`+28`, divides by four through helper `0x1c4100`, multiplies the quotient by
10,000,000, then adds that time difference to the epoch timestamp. Therefore:

`timestamp = epoch + floor(uint64(turn × 15000)/4) × 10000000`.

The four-byte turn is not a 60 Hz OpenTPW tick. The separate clock lane has
traced its sole update writer and nominal 248 ms scheduling; consult that
lane's witness for pause, catch-up and speed controls. This document proves
the date consumer's conversion, not runtime wall-clock stability. For normal
construction, one turn adds 3750 simulated seconds. A day requires 23.04
turns mathematically; actual date transitions occur at integer turn samples.

Actual import resolution: app glue `0x1c5e2c` imports the setter; bullfrog
transition vector data `0x186c` resolves it to code `0x1bb50`. Its call at
`0x1bb94` reaches macdoze `SystemTimeToFileTime`. Getter vector data
`0x1864` resolves to `0x1bbfc`, calling `FileTimeToSystemTime` at `0x1bc70`.
The app extracts date components through this timestamp API, rather than
dividing into fixed 30-day months. The exact civil/leap-calendar implementation
remains the macdoze conversion dependency; merely naming the API is not a
proof of every leap-year edge case.

Calendar update `0xe3f0c` compares extracted day/month with its saved previous
values, emits day/month events on changes, and stores the new values. Year
changes generate the separately constructed year event. Initial date is
directly established; Mac month/hour extraction and Windows equivalence need
the conversion implementation/capture to close the remaining boundaries.

## Staff, research and maintenance

**Wages, ECON-043.** `0xf46bc` maps staff role byte `+2` into the five role
indices and loads grade `+484`. At `0xf4744–0xf4760` it multiplies global
balance `+832 + 4×role` by `+748 + 16×grade`. The parallel candidate wage
getter `0xf477c` uses the same product. Embedded SAM descriptors name
`BaseWage` at data `0x36574` and `PayMultiplier` at `0x366dc`; their runtime
schema offsets warrant an independent schema-reader check. The actual PC
SAM values yield monthly grade-0 wages 40/120/60/80/140. Staff event handler
`0xf2b5c` routes type 12 to debit routine `0xf3364`, which calls this wage
getter and bank withdrawal. Thus monthly debit cadence and multiplication
are independently established. Training manager also routes month type 12
through `0xf7a64 → 0xf7e18 → 0xfc1c4`.

**Training, ECON-008/013.** At `0xfc1c4` the manager counts workers per role,
integer-divides each role budget by that count, and calls `0xf3588` once per
worker. That routine charges the allotted money, divides it by the grade's
training-price field, caps the resulting increment at 100, and adds it to
percentage byte `+488`. Crossing 99 increments grade and subtracts 100 from
the accumulated percentage. Grade 4 rejects training. The full allotted
money is charged before integer point truncation; leftover money is not
automatically refunded. Role-budget division truncation can leave part of
the total budget unspent. Newly promoted staff have field `+500` restored
to 100.

**Skill, ECON-037.** Function `0xf41dc` directly computes
`trunc_u32(20 × (grade + percentage/100))`, using data double `0x5618 = 100`
and float `0x5620 = 20`. It is called by staff panel builders `0x14adf0`,
`0x14aff4`, and `0x16d91c`. This contradicts the prototype's
`grade × 25 + percentage/4`; grade 4 at zero progress returns 80.

**Mood/strike, ECON-014.** Initialization `0xf29fc` stores 100 at `+500/+504`.
The strike/rest routine `0xf4900` has a real transition to strike with actual
navigation to the bus stop, and calls the staff-manager strike test. Initial
100 is proven, permanent happiness is contradicted. Complete mood deltas
remain in `0xf445c–0xf46bc`, `0xf3d8c`, and `0xf4900`.

**Research, ECON-015..018.** Researcher update `0xf0284` skips broad states
3/4/5, computes turn modulo 20 at `0xf02b4–0xf02d8`, and calls contribution
`0xf0728` only at remainder zero. The contribution loads one grade-dependent
integer from balance `+1052 + 12×grade` and passes it to lab `0xf0df0`.
The descriptor at data `0x36b50` identifies the ResearchAbility lead; the
full schema mapping remains independently checkable. It is not called once
per calendar day. The broad-state exclusion and workload also matter: this
is not an unconditional hired-headcount sum.

For each active, unfinished category project, the lab adds single-precision
points equal to `ability × category_effort / sum_active_efforts × workload/100`.
The sum routine is `0xf1238`; the calculation is `0xf0e50–0xf0ec0`;
`0xf2328` adds points to project progress and completion predicate `0xf2494`
is progress >= cost. Category effort and workload setters clamp at 100.

Group updater `0xf15b4` counts projects **of the same category whose group
is less than current_highest_group + 1**, and compares integer percent
completed with threshold indexed by current_highest_group. It may repeatedly
advance through groups up to 7. Thus it tests cumulative completion through
the current group, not only the preceding group's completion. Descriptor
`PercentageForThisTech` is at data `0x373c0`; arithmetic/counting at
`0xf1618–0xf168c` is direct.

Project selection `0xf0ef0` and reverse selector `0xf1088` scan list order
with category, group and completion checks. There is no cheapest-cost
comparison in these selectors. Project-list creation `0xf0be4` iterates the
catalogue; cost comparisons there identify a most-expensive project for UI
rate normalization, not a sort. Exact catalogue iteration order and which
selector drives each user action remain necessary before replacing all
ordering rules. Category 4 has parent-ride/build-availability predicates at
`0xf0f54–0xf0fe4`; constructors `0xf2178/0xf2224` are the next dependency
for upgrade/add-on category membership.

**Wear/repair, ECON-021..024.** Ride update `0xe077c` enters every eight turns
for an operating object; it calls wear `0xdec2c`. Wear additionally gates on
turn modulo 64, nonzero upgrade wear field, a mode predicate and open/flag
conditions. It subtracts derived amount `D` from float object `+64` and
`0.02×D` from float `+68`, independently clamped to [0,100]. `D` comes
from operating speed/capacity parameters and upgrade fields through
`0xde904`; simply subtracting raw WearRate each day is contradicted.
That function combines two operating ratios and branch adjustments before
multiplying by the upgrade wear field. Script getters `0xb5b40/0xb5be0`
and SAM descriptor-to-offset mapping are required to label every operand
and recover the complete equation without guessing.

Full repair completion `0xdef2c` writes 100 only to `+64` (`0xdef78–0xdef88`)
and clears maintenance flags/assignment. It does not restore `+68` there.
Breakdown path `0xe077c` tests the truncated values of both fields; zero
remaining-life value reduces `+68` by five on the relevant transition and
requests breakdown. This corroborates the manual's separate wear/lifetime
and reliability warnings without identifying every display label.

Mechanic arrival `0xd9c0c` computes upgrade duration as grade work field
`× DurationOfUpgrade` (`0xd9d48–0xd9d74`), or ordinary repair countdown as
`floor(work_field × (100 - trunc(repair_state))/100)`
(`0xd9d7c–0xd9dc0`). The latter uses integer division by 100. Repair-state
handler `0xd9e04` decrements countdown once per call and, at zero, also
waits for the object's fix animation predicate before calling full repair.
Movement/arrival is a real dependency; instant dispatch and game-hour units
are not supported. Cleaner state `0xd60c8` waits until
`turn > cleaning_start_turn + grade_work_field`, then removes litter from
its actual assigned map cell via `0xd8950`. Park-wide minute-based cleaning
is contradicted; toilet cleaning has separate paths `0xd6230/0xd6350`.

## Guest money and park statistics

Guest charge `0xeaa80` calls price getter `0xe1f70` (object `+400`), sends
that amount to object receipt `0xe1b60`, and subtracts exactly it from guest
cash `+416`. Receipt deposits the same amount into the bank at `0xe1b8c`
and records object takings/history. Goods cost routine `0xe1e58` increments
object costs and withdraws from the bank. Guest completed-use routine
`0xeaaf8` invokes those goods-cost calls for category selectors 1 and 2.
For selector 2 it also gives the goods-cost amount to guest cash. This
needs sideshow-winning/cash-prize semantics traced before treating the
effect as a universally paid prize.

Goods getters use the current object cost field `+388`; shop cost
`0xe2094` derives it from current quality/special-ingredient state. Thus
`InitCostOfGoods` is not sufficient as a constant transaction cost.
Admission receipt `0xcc568` adds the entrance fee to bank, annual profit
and the admission accumulator. All monetary branches must eventually
be connected to their original event timing and affordability checks.

The analyzer composite at `0xc7b24` was inspected through its real monthly
history caller `0xc163c → 0xc17b8`. It combines a capped visitor component,
counts of rides/shops/sideshows/features and upgraded rides, and five capped
staff-role counts. It does not read the happiness/cleanliness formula used
by OpenTPW. Its result is written to analyzer history at `+0x213b0`.
The **mapping of this statistic to the original park-rating UI has not yet
been proven**, so this is a concrete candidate, not grounds to replace
ECON-027 by a guessed formula. The next dependency is the consumer of that
history, with category counters `0xc5864` and staff counters `0xc4064`.

**Scrap, ECON-025.** The actual object deletion/sale path `0xdbfa8` calls
`0xe25e8` at `0xdc05c` and deposits the result at `0xdc070`. This getter
multiplies **the base catalogue cost at catalogue +440**, without summing
upgrade costs, by the percentage returned by `0xe2424`, then integer-divides
by 100. The percentage function uses elapsed timestamp since object `+20`;
its year divisor is exactly 365 days and its initial-period divisor is
exactly 30 days. It selects the current upgrade's percentage fields at
catalogue `+392/+396/+400/+404 + 64×upgrade` for age-year buckets
0/1/2/other. An unused object (`+412 == 0`) in the first 30 days may return
100 when the catalogue's first percentage field is positive. Otherwise it
uses the age bucket's percentage. This is a separate quote from analyzer
park valuation, which sums costs through the current upgrade and includes
weighted map infrastructure. The initial-period predicate and elapsed-day
divisors should be retained in any Mac-backed implementation.

## Recommended implementation follow-up

First add an explicit source/platform distinction before changing behavior
that only the Mac executable proves. In a Mac-backed rule set, replace
annuity principal amortization with fixed `M`, store months repaid, and quote
early payoff as remaining installments. Keep annual profit bookkeeping
separate from bank balance and loans received. Add tests for all eight SAM
offers and repayment completion/retake/early-payoff ordering.

Replace the prototype skill calculation and preserve the proven training
money/point truncation. Use the independently proved turn schedule to drive
calendar, research and wear separately; do not convert all of them to
day-end operations. Preserve distinct repair/life fields, health-scaled
repair duration, assigned-cell cleaner jobs, state-filtered research and
workload distribution. UI rating, full wear equation, exact research order,
initial keys and Windows equivalence remain explicit evidence dependencies.

The manual supports monthly wages, real scientists, staff rest/strikes,
preventive maintenance and three tickets per key. It does not prove the
quantitative formulas above. `startingkey1` remains unknown; no claim in this
lane restores the superseded four-ticket earning interval.
