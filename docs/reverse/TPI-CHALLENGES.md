# Theme Park Inc challenges: settings and the firing line

This note records what a Theme Park Inc park's challenge system reads and where it ends, so that the slice's refusal of the system can be lifted deliberately rather than by guesswork. The full system (slot layout, state machine, offer schedule, outcomes and types) is traced in [TPI-CHALLENGE-SYSTEM.md](TPI-CHALLENGE-SYSTEM.md). It uses the identified English no-CD TPI `Game.exe` (SHA-256 `77ea0c41410aad7c94a5eda658e31cb4ac05f7253aaf6746ad5e8a90afbd967a`) and the shipped data; the game was not launched.

## The keys the executable reads

[BIN:TPI-EXE:0x99D618 challenge settings] The executable's own setting names are `DaysBetweenOffers` (`0x99D618`), `MissionNumberForFirstChallenge` (`0x99D654`), `ShortTimeLeftWarningAt` (`0x99D690`), `Challenges` (`0x99D6CC`), `Limit` (`0x99D744`), `FiringLineForRank` (`0x99D780`), `ChallengeType` (`0x99D7F8`), `ChallengesInThisLevel` (`0x99D834`), `YearsBeforeStarting` (`0x99D8AC`) and `SpamEmailsPerYear` (`0x99D8E8`).

The retail values sit in the global `Data/levels/Standard.sam`: `Challenges.DaysBetweenOffers` 20, `Challenges.MissionNumberForFirstChallenge` 0, `Challenges.ShortTimeLeftWarningAt` 20 (parsed into `0xA028F4`, which no code reads: Theme Park Inc has no time warning, and the slot's warning byte `+0x8E` is only ever cleared), and `FiringLineForRank[0..5].Limit` 255, 5, 5, 5, 5, 5 — the floor a promotion to each rank puts under the number of challenges a player may still fail before the board acts (see below). `SpamBalance.SpamEmailsPerYear` is 1.

[BIN:TPI-EXE:0x5C76BD level challenge rows] A level's own `Data/levels/<level>/Standard.sam` lists its challenges under `ChallengesInThisLevel[n].ChallengeType`, but the loader `0x5C7630` takes each of the first ten values as a row number of `Challenges.sam`, not as a type: a positive value n builds row `Challenges[n]` into the first empty slot of ten. The science level lists 2, 4, 5, 14, 13, 18, 21, 8, 20 and 22, rows whose types are 2, 35, 25, 46, 36, 41, 56, 17, 48 and 17. The parsed settings land at `0xA028EC` (`DaysBetweenOffers`), `0xA028F0` (`MissionNumberForFirstChallenge`), `0xA028F4` (`ShortTimeLeftWarningAt`), `0xA028F8`–`0xA0290C` (`FiringLineForRank[0..5].Limit`), `0xA02914` (the level list, twenty entries of which the loader reads ten) and `0xA02968`/`0xA0296C` (`YearsBeforeStarting`, `SpamEmailsPerYear`); the global file is parsed first with a reset to defaults and the level's file over it. The definitions themselves are the shared `Data/Challenges.sam`, whose header still says Theme Park World and whose `Challenges[n]` rows carry `Type`, `TargetTime`, `CashPrize`, `CheckAtEndOnly`, `Independent`, `MaxDaysTilTrigger`, `DaysDelay`, `TriggerData`, `Sender`, `ScriptIndex`, `GracePeriodLimit`, `SharePriceEffectWon`/`Lost`, `GTPrize` and `MissionNeededToActivate`.

## Where it ends

[BIN:TPI-EXE:0x5C48DD lost challenge] The challenge system's lost branch logs `Lost the challenge!!!` and posts notification id 7 through the payload constructor `0x5CEE50`; the tag system turns that into advice `0x1A3`, whose response plays speech 870 and whose tag `0x5F` holds `TAG_SYSTEM.str` entry 167 — the letter that ends the player's employment after too many failed challenges. The bank's red-month letter is entry 166 of the same table (see [the bank mail trace](TPI-BANK-MAIL.md)).

[BIN:TPI-EXE:0x5C4857 firing line countdown] The letter is not posted on every loss. The lost branch first decrements a counter held in the first word of the career object at `0xBFC484` (a 0x4740-byte singleton that also holds the player's rank at `+0x1060`); a challenge's own loss count at `+0x5C` makes sure one challenge takes only one off. [BIN:TPI-EXE:0x5C48B6 firing line post] The post follows whenever the counter is no longer positive (`cmp 0` / `jg` past it), so the letter arrives on the loss that exhausts the line and again on every loss after it. Each challenge slot is a 0x90-byte record that a new offer overwrites whole (`0x5C753D`, `0x5C77C9`), so the loss count starts at zero for every challenge.

[BIN:TPI-EXE:0x74BDD1 career firing line] The career object's reset (`0x74BB40`, called from its constructor and two other entry points) sets the rank to 1 and the counter to a fixed 5. `FiringLineForRank` is read only on promotion: the handler of `Promotion Message Received` (`0x5F1148`) calls `0x74C450`, which stores the new rank and raises the counter to that rank's limit (the parsed table at `0xA028F8`) when the counter is lower. A promotion never lowers it, so rank 0's limit of 255 is not a starting value; nothing in the traced code sets rank 0.

So TPI has two ways to end the game, and both are letters: the six-month red letter and the challenge firing letter. Dismissing either sets the lost state and opens the loss window, "BANKRUPT!" or "Fired!" (see [the bank mail trace](TPI-BANK-MAIL.md#the-letter-window-and-the-end-of-the-game)). OpenTPW starts the counter at 5 and counts lost challenges down from it in its port of the challenge system (`ThemeParkIncChallenges.FiringLine`, using each slot's own loss count), handing over `ThemeParkIncAdviceMail.ChallengeLost` on every loss that leaves it at zero or below. Promotions are not modelled, so the counter is never raised. OpenTPW keeps it with the park's challenge system rather than in a career object and saves it in the Science continuation save (whether the original saves its career object is not traced).

## How the slice runs challenges

Until November 21, 2026 `EconomyRules.ThemeParkIncMoney` refused challenges, because `BalanceSettings` reads Theme Park World's schedule keys, which Theme Park Inc's data lacks. The slice now runs Theme Park Inc's own system instead (`ThemeParkIncChallenges`), built from `DaysBetweenOffers`, `MissionNumberForFirstChallenge`, the level's rows and `Challenges.sam`; Theme Park World's objectives and golden tickets stay off in a Theme Park Inc park. What it measures, what it gates and what stays open is listed in [TPI-CHALLENGE-SYSTEM.md, section 10](TPI-CHALLENGE-SYSTEM.md#10-port-status). The promotion model that would raise the firing line from `FiringLineForRank` is still missing.
