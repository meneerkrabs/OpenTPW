Start Theme Park Inc in OpenTPW

Theme Park Inc / Sim Coaster (2001) can run as an experimental slice in OpenTPW's own engine. Bring your own installed or extracted game files, then launch OpenTPW. The original autostart.exe is not needed to run it.

This is a limited building-and-guests experiment, not the complete original game. Read what works and what is missing before starting a park.

Which build should I use?

Availability checked 14 October 2026: the published v0.7.19 desktop release does not contain the new TPW/TPI edition chooser. That chooser is reviewed in desktop starter PR #146 for a future release. A published pull request is not a released download.

The browser at play.opentpw.io already offers explicit experimental Theme Park Inc starts. For a current desktop package, use the command below. Check the release notes when a newer package becomes available.

Use the normal OpenTPW download and platform instructions for Windows, macOS or Linux. OpenTPW supplies its engine and runtime, not the original game data.

1. Prepare your game files

Choose your own Theme Park Inc / Sim Coaster installation, or data already extracted from your copy. A folder containing only an installer or autostart.exe is not a ready game-data folder. You need the folder containing Data, with its global, language and level files:

Theme Park Inc/
└── Data/
    ├── global/
    ├── Language/
    └── levels/
        ├── arabian/  (if present)
        ├── science/  (if present)
        └── water/    (if present)

The eligible worlds are Arabian, Science and Water. The desktop chooser lists detected, available worlds; in the browser list, choose one that is present in your files. Your copy may contain fewer of them, and a missing world is refused. Do not combine Theme Park World and Theme Park Inc files in one folder; OpenTPW validates the edition and rejects a mismatched or mixed selection.

If your copy is still in installer cabinets, extract the data before selecting it. The existing extraction and running reference explains that folder layout. This site does not provide or download game files.

2. Use the desktop edition chooser

For a build containing PR #146: this is the new OpenTPW setup window, not the original game's launcher.

  1. Start OpenTPW and select Theme Park Inc / Sim Coaster (Experimental) in its edition choice. Select Theme Park World for TPW files instead.
  2. Choose the folder containing your TPI Data, type its path, or drag the folder onto setup. Selecting Data itself also works on desktop.
  3. Wait for validation, then choose one of the available Arabian, Science or Water worlds and finish setup.

OpenTPW rechecks the folder and world before starting and remembering the choice. Cancel or an invalid selection keeps the previous settings. TPI's remembered path/world is separate from the TPW path, CD and bonus settings. TPI enters the experimental world directly, without the TPW island lobby.

To reopen this chooser in a build that contains it, start OpenTPW with --setup. Explicit command-line game/tool starts keep their existing precedence.

Current desktop package: start a world explicitly

If your package has the older path-only setup, choose the installation and world on the command line. Replace the example folder with yours; replace science with arabian or water only when that world is present:

# macOS / Linux, from the extracted OpenTPW folder
./OpenTPW --game-path "/path/to/Theme Park Inc" --load-original-level science

# Windows PowerShell, from the extracted OpenTPW folder
.\OpenTPW.exe --game-path "C:\Games\Theme Park Inc" --load-original-level science

Do not use the TPW lobby, sandbox or campaign start for TPI data. The explicit world command enters the same experimental route used by the new chooser and browser.

3. Start in the browser

  1. Open play.opentpw.io. In the start list, choose Theme Park Inc — experimental Arabian, Science or Water for a world present in your files.
  2. Choose Choose folder and select the extracted installation folder containing Data. Allow the import of the selected world's complete browser-supported file set to finish.
  3. Use Play when the kept files are ready, or let the completed folder start enter the selected world. OpenTPW refuses files that do not match your selected edition or world.

Your files remain on your device. Browser storage may be unavailable, cleared or too small; selecting the folder again recovers missing data. A partial import does not make a world ready. Once a park has opened, reload the page before switching installation. If a startup error asks you to reload, follow that message before retrying. See browser import and retry behaviour and kept-file storage.

When a build offers an OpenTPW layout checkpoint, loading it starts a new session with that layout. It is separate from a native park save or full simulation continuation. See the checkpoint boundaries.

Building is free because the TPI economy is disabled. Guest rules are shared with TPW, and some script effects and rendering details remain unresolved. No original TPI gameplay or visual parity is claimed. The technical slice reference records the exact capability policy and current gaps.

If the world will not start

  • No TPI choice on desktop: check your build. The chooser described here is the PR #146 addition, not a v0.7.19 release feature. Use the explicit command above with an older package.
  • Wrong edition or no available world: select TPI files, keep installations separate and check that the chosen world's folder is present. Do not rename a TPW world into a TPI world.
  • Missing data or a decoder error: setup's directory check is not proof that every required asset is complete. Restore the files from your own installation or extraction and report the exact error.
  • Browser import or kept-file failure: reselect the same folder and retry the complete import; reload first if a park has opened or the startup error asks you to do so.

For a report, include your OpenTPW version, platform, game edition and world plus the error text. Keep game files out of public reports. Continue with platform installation help or GitHub issues.
